# 문서 워크스트림 핸드오프 브리프 (새 창) · 2026-08-22

> C-1 문서 관련 결함을 **하나의 창에서 묶어** 진행하기 위한 핸드오프. 문서엔진·서식·저장·다운로드·사업자등록증·안전정보를 한 번들로.
> 근거: `TRIAGE_safe-defects-83`·`C-결정시트`·기존 `RECEIPT_*`. 이 브리프는 스코프·현재상태·경계만 넘긴다(실작업은 새 창).

---

## 0. 왜 한 창인가
서식 목록·PDF 생성·파일 저장(버킷)·다운로드·사업자등록증·안전정보가 **문서엔진·스토리지라는 공통 축**을 공유. 흩어서 하면 버킷 정본·PDF 파이프라인이 중복·충돌. **한 창에서 저장→생성→다운로드 파이프라인을 일괄 설계.**

## 1. 번들 스코프 (결함 매핑)
| 대장# | 화면/기능 | 현재 상태 |
|---|---|---|
| ⑬ | `my-company` 사업자등록증 업로드 | POST /companies/{id}/upload-file 배포됨 · **저장 0건**(성공한 적 없음) · 버킷 정본 미정 |

## 2. 저장(버킷) 결정 — 정본
- **C-결정시트 채택**: 버킷 정본 = **`company-docs`**. `company-files`는 v2.2 때 신규 생성됐으나 정본 아님 → 통일.
- **`tai-files` 버킷 신설**: 교육 증빙(법정 증적) 저장용 — C-3 결정.
- 새 창이 **버킷 정본 1개 확정 + 신설**부터 정리하고 PDF/업로드를 그 위에 얹을 것.

## 3. 현재 확인된 사실 (직독/DB 기준)
- `document-forms` = 260건, 무인증 응답(§80/C-0 정책 별건).
- `document_form_master` = 63행, penalty_summary 22/63.
- `company_files` 0행(⑬ 성공 이력 없음), 비공개 버킷 `company-files` 존재 + `company-docs` 존재(둘 다 있음 → 택1).
- PDF: Gotenberg(Docker Chromium) Railway Singapore, 내부 URL `http://gotenberg.railway.internal:3000` — PDF 파이프라인 인프라는 있음.

## 4. 경계 (절대)
- **법령엔진 판정로직·서식 데이터 원천(GPT 소관)** 불변 — 문서 창은 **표시·저장·생성·다운로드**만. 법령해석·판정 금지.
- company_scope·권한가드·C-2 값어휘 불변.
- 「PDF리포트」 용어 금지 → **「안전관리설계서」**.

## 5. 권하는 착수 순서 (새 창)
1. **버킷 정본 확정**(company-docs) + `tai-files` 신설 → 저장 계약 1개로.
2. **⑬ 사업자등록증** 업로드→저장→조회 파이프라인(버킷 위에서).
3. **⑱ 서식 PDF 생성**(Gotenberg 파이프라인) → 다운로드.
4. **§49 재대조**(document-forms vs document_form_master 원천) → penalty 처리(㊾).
5. ⑳ 안전정보 = 내림(결정) 반영.

## 6. 이 창(기획/실행)에서 넘기지 않는 것
- 문서 밖 잔여(§66 weather·§62/§63 건설점검·§72 notifications·잔여 라이브)는 **기존 창**에서 계속.
- GPT 파킹(§57·⑫)·앱창(§75-83)은 각 소관.
