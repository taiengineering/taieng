## 한 문장 정의

> Phase 1은 factories의 110개 컬럼에서 소비자 입력을 손실 없이 FacilityProfile로 투영(Projection)하고 다시 복원 가능한지 검증하는 작업이다.

---

## 핵심 원칙 (불변)

```
1. FacilityProfile은 factories를 대체하지 않는다.
   factories = Source of Record
   FacilityProfile = Projection Layer

2. UNKNOWN은 값이 아니다. 상태(state)이다.
   state = UNKNOWN, value = null  ← 유일한 표현
   value 필드에 UNKNOWN 문자열 저장 금지
   value 필드에 0 저장 금지
   value 필드에 false 저장 금지

3. Phase 1 산출물은 엔진 입력으로 사용하지 않는다.
   FacilityProfile → Track A 연결 금지
   FacilityProfile → Track B 연결 금지
   FacilityProfile → Check Engine 연결 금지
   지금은 저장·복원·감사용 자산이다.

4. factories 110개 컬럼은 Phase 1 동안 건드리지 않는다.
   컬럼 삭제 0 / 컬럼 변경 0 / 데이터 이동 0
```

## TriValue / TriList 구현 규칙

```python
# TriValue 유일한 표현
{ "state": "PRESENT",  "value": 280,    "provenance": "INPUT" }
{ "state": "ABSENT",   "value": null,   "provenance": "INPUT" }
{ "state": "UNKNOWN",  "value": null,   "provenance": "INPUT" }

# Boolean도 동일 — 세 가지를 구분
{ "state": "PRESENT",  "value": true,   "provenance": "INPUT" }
{ "state": "PRESENT",  "value": false,  "provenance": "INPUT" }
{ "state": "UNKNOWN",  "value": null,   "provenance": "INPUT" }

# null → UNKNOWN 자동 변환 (0 저장 금지)
# factories.employee_count = null  →  { state: UNKNOWN, value: null }
# factories.employee_count = 0     →  { state: PRESENT, value: 0 }  (명시 입력)
```

---

## Provenance 구조

```
INPUT    = 사용자가 직접 입력한 값
INFERRED = KSIC 추론 등 시스템이 채운 값  (Phase 1에서 구조만 확보)
DEFAULT  = 기본값 적용한 값
```

Phase 1에서 INFERRED 실제 생성 불필요. 구조(스키마)만 확보.

## FacilityProfile v1.0 스키마

### Phase 1 필수 구현

```
식별:
  profile_id      UUID PK
  factory_id      UUID FK → factories.id
  profile_version integer (1부터 시작)
  sector          text
  ksic_code       text
  created_at      timestamptz

workforce:
  regular_workers      TriValue<int>   ← factories.employee_count
  subcontract_workers  TriValue<int>   ← factories.subcontractor_worker_count
  total_workers        TriValue<int>   ← factories.total_worker_count_calc

building:
  use_code    TriValue<text>   ← factories.building_use_code
  floor_area  TriValue<float>  ← factories.building_area
  floor_count TriValue<int>    ← factories.floor_count

metrics:
  construction_amount  TriValue<float>  ← factories.construction_amount
  electrical_kw        TriValue<float>  ← factories.electrical_capacity_kw
  gas_capacity         TriValue<float>  ← factories.gas_capacity_m3 or gas_capacity_kg

provenance:
  입력값_fields  [field_name, ...]   ← INPUT 출처 목록
  확장값_fields  [field_name, ...]   ← INFERRED 출처 목록 (Phase 1: 빈 배열)
  기본값_fields  [field_name, ...]   ← DEFAULT 출처 목록
```

## 저장 구조 (C안)

```sql
-- 메인 테이블 (정규화 컬럼 — 조회용)
CREATE TABLE facility_profiles (
  id                          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  factory_id                  UUID NOT NULL REFERENCES factories(id),
  profile_version             INTEGER NOT NULL DEFAULT 1,
  sector                      TEXT,
  ksic_code                   TEXT,

  -- workforce (TriValue 분리 저장)
  regular_workers_state       TEXT,   -- PRESENT|ABSENT|UNKNOWN
  regular_workers_value       INTEGER,
  regular_workers_provenance  TEXT,   -- INPUT|INFERRED|DEFAULT

  subcontract_workers_state   TEXT,
  subcontract_workers_value   INTEGER,
  subcontract_workers_provenance TEXT,

  total_workers_state         TEXT,
  total_workers_value         INTEGER,
  total_workers_provenance    TEXT,

  -- building
  use_code_state              TEXT,
  use_code_value              TEXT,
  use_code_provenance         TEXT,

  floor_area_state            TEXT,
  floor_area_value            NUMERIC,
  floor_area_provenance       TEXT,

  floor_count_state           TEXT,
  floor_count_value           INTEGER,
  floor_count_provenance      TEXT,

  -- metrics
  construction_amount_state   TEXT,
  construction_amount_value   NUMERIC,
  construction_amount_provenance TEXT,

  electrical_kw_state         TEXT,
  electrical_kw_value         NUMERIC,
  electrical_kw_provenance    TEXT,

  gas_capacity_state          TEXT,
  gas_capacity_value          NUMERIC,
  gas_capacity_provenance     TEXT,

  -- provenance 요약
  input_fields                TEXT[],    -- INPUT 출처 목록
  inferred_fields             TEXT[],    -- INFERRED 출처 목록
  default_fields              TEXT[],    -- DEFAULT 출처 목록

  -- 감사용 JSON Snapshot (전체)
  profile_snapshot            JSONB NOT NULL,

  created_at                  TIMESTAMPTZ DEFAULT now(),
  UNIQUE(factory_id, profile_version)
);
```

## factories → FacilityProfile 변환 규칙

| FacilityProfile 필드 | factories 소스 컬럼 | 변환 규칙 |
|---|---|---|
| regular_workers | employee_count | null → UNKNOWN / 값 있음 → PRESENT |
| subcontract_workers | subcontractor_worker_count | null → UNKNOWN |
| total_workers | total_worker_count_calc | null → UNKNOWN |
| use_code | building_use_code | null → UNKNOWN |
| floor_area | building_area | null → UNKNOWN |
| floor_count | floor_count | null → UNKNOWN |
| construction_amount | construction_amount | null → UNKNOWN |
| electrical_kw | electrical_capacity_kw | null → UNKNOWN |
| gas_capacity | gas_capacity_m3 or gas_capacity_kg | 둘 다 있으면 m3 우선 |
| sector | sector | null → DEFAULT(INDUSTRIAL 시도) |
| ksic_code | ksic_code | null → UNKNOWN |

**절대 금지**: 0 채우기 / false 채우기 / "UNKNOWN" 문자열 value 저장

## 성공 기준 (SC-01 ~ SC-05)

```
SC-01: 입력 손실 0건
  factories → FacilityProfile → 저장 → 재로드 원본 == 재로드 100%

SC-02: UNKNOWN 보존
  CASE-02 (모든 값 null) → 전 필드 state=UNKNOWN
  0 변환 0건 / false 변환 0건

SC-03: Provenance 보존
  모든 PRESENT 값에 대해 INPUT/INFERRED/DEFAULT 구분 가능

SC-04: Round Trip 성공
  CASE-01 ~ CASE-04 전부 PASS
  CASE-01: 화성 제2공장 (INDUSTRIAL, C28, 280명)
  CASE-02: 빈 사업장 (모든 값 null)
  CASE-03: 건설현장 (공사금액 49억)
  CASE-04: 건설현장 (공사금액 50억)

SC-05: factories 무변경
  컬럼 삭제 0 / 컬럼 변경 0 / 데이터 이동 0
```

## Phase 1 완료 정의

> 동일한 사업장 입력이 factories와 FacilityProfile 두 경로 모두에서 100% 재현되며,
> null이 0 또는 false로 변질되지 않고 provenance(INPUT/INFERRED/DEFAULT)를 추적할 수 있다.

## 구현 순서

```
1. facility_profiles 테이블 DDL (Supabase migration)
2. FacilityProfile 변환 서비스 (Python)

   provenance 자동 감지
3. profile_snapshot JSON 생성
4. 저장 엔드포인트 (POST /facility-profiles/{factory_id})
5. 복원 엔드포인트 (GET /facility-profiles/{factory_id})
6. SC-01~SC-05 검증 엔드포인트
```
