## 4. 분석 질문 4: 별도 테이블/입력이 필요한 SCOPE

### 4-1. 소방시설 + 소방대상물 (406건, 전체 SCOPE의 46.8%)

**문제**: 이 의무들은 사업주가 아닌 **관계인, 소방시설업자, 감리업자, 시·도지사** 등의 의무다.

실증:
- 소방시설 의무 executor_text 1위: 시·도지사 (12.2%), 소방서장 (11.9%), 관계인 (6.8%)
- 사업주 비율: **0%** (소방시설 SCOPE에 사업주 의무 없음)
- 소방대상물 의무: 관계인 22.8%, 소방서장 14.8%, 사업주 **0%**

**결론**: 소방시설/소방대상물 SCOPE 406건은 **TAI 타겟(사업주)과 무관**한 의무다.  
별도 테이블이 필요한 것이 아니라, **처음부터 제외해야 할 범주**다.

### 4-2. 소화설비 (254건)

- 사업주 의무 비율: 25.5% (12건) — 소방법이 아닌 산업안전보건규칙 소화설비
- 나머지 74.5%: 관리자, 시장·군수·구청장 등
- 연결 방식: `has_chemical_substance`, `has_boiler`, 화학설비 보유 여부 → 소화설비 설치 의무
- **별도 필요**: 화학설비·위험물 취급 여부 input 필드 (현재 `is_hazardous_material` boolean만 존재)

### 4-3. 작업환경측정 (66건)

- 사업주 의무 비율: **48.8%** (가장 높음)
- 발생 조건: 유해인자(분진, 소음, 화학물질, 방사선 등) 취급 여부
- 현재 `factory_process`에 process_id 등록되어 있으나, 유해인자와 process의 연결 테이블 미존재
- **별도 필요**: 유해인자 분류 테이블 (공정→유해인자 매핑)

### 4-4. 안전장치 (63건)

- 사업주 의무: 0% (판매자, 운영자, 건설기계 제조자 의무)
- **제외 대상**: TAI 타겟 아님

### 4-5. 방호장치 (52건)

- 사업주 의무: **62.5%** (15건) — 가장 직접 연결 가능한 SCOPE
- 발생 조건: 크레인, 프레스, 로봇, 컨베이어 등 보유 시
- `equipment_assets`의 CRANE, PRESS, CONVEYOR 코드와 직접 연결 가능
- **별도 불필요**: 현재 입력 데이터로 커버 가능

## 6. 결론

### B. 일부 가능, 별도 입력/테이블 필요

### 근거

**가능한 부분 (즉시 구축 가능)**

1. 방호장치 56건: `equipment_assets` (CRANE/PRESS/CONVEYOR/ROBOT) → 방호장치 SCOPE 연결  
   규칙: `{equipment_type_code} → scope_token 매핑` 테이블만 있으면 됨

2. 사업주 의무 A+B+C+D+E1+E2 (777건): 현재 입력 데이터로 커버 가능  
   KSIC + employee_count + has_* + equipment_assets 조합

**불가능한 부분 (추가 필요)**

1. 소방시설/소방대상물 SCOPE 406건: **TAI 타겟(사업주)이 아닌 의무**. 제외하면 됨.  
   별도 테이블이 문제가 아니라 엔진이 이를 오분류하고 있음.

2. 작업환경측정 66건: 유해인자(분진, 소음, 화학물질) 분류 테이블 필요.  
   현재 `factory_process`만으로는 어떤 유해인자가 있는지 판별 불가.

3. E3 UNRESOLVED 381건: 참조 조문 해석 없이 조건 판별 불가.  
   Binding 계층으로 해결 안 됨. 별도 엔진 또는 인간 검토 필요.

### 핵심 발견

> SCOPE 868건의 46.8%(406건)는 소방시설/소방대상물로,  
> 이 의무들의 주체는 시·도지사, 소방서장, 관계인 등이며 **사업주는 0%**다.  
> 즉 SCOPE의 절반은 TAI 타겟과 무관하다.  
> TAI에 필요한 실효 SCOPE는 약 100건(11.5%)이며,  
> 이 중 방호장치 56건은 현재 데이터로 Binding 가능하다.
