## 핵심 전략 — 반복 깎아내기, 매번 "완벽한 것만"

```
1. Kiwi로 잘못된 executor 색출  (현재 11,529건: 갈래1 7,065 + 갈래2 4,464 + 비주어 408)
2. 그중 "완벽한 것만" 의미절 수정 (executor_fixed 채움 → 통과분만 executor_text 반영)
3. 다시 Kiwi로 색출 → 남은 잘못된 것 (수가 줄어듦)
4. 또 완벽한 것만 수정
5. 반복… 완벽하지 않은 것은 매 회차 손대지 않고 남겨둠
6. 더 못 깎을 만큼 작아진 나머지(어려운 소수) → LLM이 처리 (수가 작아 환각 통제 가능,
   원문 대조 검증 거침, 코어 아닌 별도 단계 격리)
```

## "완벽"의 정의 (대표 확정 — 두 조건 동시 만족)

수정 대상이 되려면 아래 둘을 **모두** 만족해야 한다. 하나라도 안 되면 이번 회차에 건드리지 않는다.

**조건 1 — 수정 후 Kiwi 재검증이 작동하는 것.**
고친 결과를 다시 Kiwi에 넣었을 때 Kiwi가 OK/FLAG로 판정할 수 있어야 한다.
- 동사어간(설치하)→명사(사업주)로 고침 → 재검증 시 Kiwi가 명사=OK 확인. 잘못 고쳐 또 동사면 FLAG로 잡힘. → 검증 그물 작동. 수정 OK.
- 사물주어(출구)를 다른 명사로 바꿈 → 바뀐 것도 명사라 Kiwi는 OK만 함. "이 명사가 진짜 주어인지"는 Kiwi가 판정 못 함 → **검증 그물 못 만듦 → 건드리면 안 됨.**
  (어제 사고: "소방관"을 잘못 빌려도 명사라 OK 통과 = 검증을 빠져나감. 이걸 원천 차단.)

**조건 2 — 무엇으로 바꿀지가 원문에서 확정되는 것.**
Kiwi는 "주어 자격(명사인가)"은 검증하지만 "주어 정체(누구인가)"는 보증 안 한다.
그러므로 바꿀 주어는 추측이 아니라 원문이 직접 말한 것이어야 한다.
- 1차 확정 소스 = 그 의미절 source_part_text **맨 앞**의 [명사 + 주격조사 은/는/이/가].
  (17조 "사업주는…", 재난법41조 "관계 중앙행정기관의 장은…" — 맨 앞이 곧 주어)
- 맨 앞이 사물(출구/구조부재)·조건절(제3항에 따라…)·생략이면 → 원문에서 확정 안 됨 → 미룸.

→ 1회차 수정 = (조건1 ∧ 조건2). 즉 "동사어간 잘림인데, 원문 맨 앞에 사전 등재된
   주체명사+주격조사가 있는 것"만. 나머지는 전부 다음 회차 또는 LLM.

## 어제 폐기된 전략 (반복 금지)
- ❌ "같은 조문의 OK executor를 빌려온다" — 긴 조문은 항마다 주어가 달라 절반이 틀림.
  (건축법시행령51조 배연설비→"소방관", 응급의료법48조→"보건복지부장관" 오선택)
  → 검증 조건1을 빠져나가는 위험한 방식. 쓰지 않는다.

## 도구 역할 (확정)
- **Kiwi = 색출 + 재검증.** "명사냐 동사냐"는 완벽. "누구인지"는 판정 못 함. 색출/분석 격리.
- **원문 맨 앞 추출 = 보정 소스.** 추측 아닌 원문 근거.
- **LLM = 마지막 소수.** Kiwi·원문맨앞으로 못 푼 어려운 것만, 수가 작아진 뒤, 원문 대조 검증 거쳐, 코어 아닌 별도 단계에. (생성/분해엔 여전히 배제 — 10장 원칙)

## 작업 안전 (불변)
- 원본 semantic_clause 직접 수정 금지. 임시 semantic_clause_fix에서 작업.
  executor_fixed에 먼저 채우고, 검증 통과분만 executor_text 반영 → 최종 원본 복사.
- 분해기·Kiwi사전 무변경. 동사어간 사전등록 금지(색출 무력화).
- 매 회차 표본 글읽기 검증 후 확대. 완벽하지 않으면 needs_review로 남김(강제 보정 금지).
- executor 한 단어가 수십만명 지시/패싱 좌우 → 틀린 보정보다 미룸이 안전.
