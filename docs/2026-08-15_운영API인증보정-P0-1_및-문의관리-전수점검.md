## 1. 문의관리 taxonomy (Track A/B)

### Track A — 분류 SoT + admin 표시
- `services/support_taxonomy.py` = 단일 SoT. 대분류 T1~T7, 소분류 36종, 처리축(resolution_axis) 3종(KNOWLEDGE / INVESTIGATION / HANDOFF).
- DB `inquiries` 테이블에 nullable 컬럼 추가: `type_code`, `subtype_code`, `resolution_axis`.
- admin 문의 리스트는 백엔드가 내려준 라벨을 그대로 렌더(프론트·DB에 taxonomy 값 중복 금지).

### Track B — HANDOFF 전용 분류기
- `services/support_classifier_svc.py` — 얇은 gpt-4o JSON 분류기. `classify_fn` 주입 가능, SoT에서 taxonomy 파생.
- **HANDOFF 확정 시에만** 호출(전건 호출 아님). 모든 LLM 호출은 best-effort — 실패는 NULL로 흡수해 본 처리를 막지 않음.
- 타임아웃: 환경변수 `SUPPORT_CLASSIFIER_TIMEOUT_SECONDS`(미설정 → None → SDK 기본값), max_retries=0.

### 문의 리스트 개편
- 접수일 필터 기본값을 **전체기간**으로(근거 없던 '최근 7일' 기본 제거).
- 필터: 인입경로 · 상태 · 문의유형(T1~T7) · 처리방식(resolution_axis) · 통합검색. NULL 필터용 `__none__` 토큰.
- 백엔드: `GET /admin/inquiries/taxonomy-options` 추가.

### E2E 확인
- `TAI-INQ-20260814-0005` → `type_code=T1`, `subtype_code=T1_SCREEN_LOCATION`, `resolution_axis=HANDOFF` 저장 + admin 라벨 표시 확인.

### 부수 보정 — admin_inquiries 인증 (INSECURE → SECURE)
- 기존 `_require_bearer`는 'Bearer ' 접두사만 확인 → 사실상 무인증. 아무 문자열로 전 고객 문의(개인정보) 접근 가능했음.
- 보정: `routers.auth.get_current_user`(Supabase 토큰 실검증) + `role_code=='001'` 확인하는 `require_admin` 부착. `/admin/inquiries` 전체(GET 목록·taxonomy-options·POST·PATCH)에 동일 경계.
- 계약: 무토큰/무효 → 401, 일반회원 → 403, 최고관리자 → 200.

## 3. billing actor 판정 (조사 전용) — 1차에서 제외 근거

payment_billing의 3개 endpoint 실제 caller를 실측한 결과:

| endpoint | 분류 | 근거 |
|---|---|---|
| POST /inicis/billing/return | PUBLIC_CALLBACK | 이니시스 콜백, authToken/authUrl 검증. 유지 |
| POST /inicis/billing/prepare | CUSTOMER_SELF | `templates/payment/billing_pay.html`이 유일 caller. **무토큰 세션리스**(user_id를 URL 쿼리로 받아 body 전달, Authorization 없음). 진입점 `tai-admin useRenewal.ts`(로그인 고객) |
| POST /inicis/billing/charge | UNKNOWN | cron/scheduler 미등록(실측: `cron_job_master` 0건 + `scheduler.py` DIRECT_HANDLERS/register_code_jobs 없음). 활성 프론트 caller 미발견. 첫결제는 return 내부 `_charge_subscription_once` 함수 직접호출(이 endpoint 아님) |
| POST /subscriptions/{id}/cancel | UNKNOWN | admin-vue3 전용 페이지 없음, tai-www 미연결, nexas는 FREEZE 구자산. 활성 호출부 미발견 |

**결론**: `prepare`는 CUSTOMER_SELF지만 현재 무토큰 세션리스 → `get_current_user` 강제 시 결제 페이지가 깨짐(인증 추가 = 결제흐름 재설계 동반). `charge`/`cancel`은 UNKNOWN. **원칙 "UNKNOWN이면 수정 금지"에 따라 payment_billing은 1차 전량 제외 → 1B로 분리.**

**billing 1B 분리 구조**
- `prepare`(CUSTOMER_SELF, INSECURE): 고객 본인성 서버 검증 설계 필요(토큰 전달 흐름 재설계).
- `charge`/`cancel`(UNKNOWN): 인증 이전에 "지금 운영에 노출해야 하는가"부터 판단. charge는 활성 caller 없이 외부 열림 → 폐기·비활성 후보 우선.

참고: 고객 결제 프론트 `nexas/service/saas.html`은 **2026-08-06 FREEZE**된 구자산(CF Pages `taieng-new` 자동배포 차단, old.taieng.co.kr만 서빙). 라이브 taieng.co.kr은 `tai-www`(Astro)가 서빙하며 billing 미연결.
