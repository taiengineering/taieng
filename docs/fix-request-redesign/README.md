# fix-request 페이지 리디자인 작업지시서

## 개요

현재 `nexas/fix-request.html` 페이지를 free-diagnosis.html과 동일한 **좌우 분할 레이아웃**으로 리디자인합니다.

- 왼쪽: 마케팅 설명 (고정)
- 오른쪽: 대화형 채팅 UI (기존 로직 유지)

## 현재 문제점

1. 채팅 박스만 중앙에 떠 있고 주변이 전부 회색 빈 공간 → 허전함
2. 로고 크기가 비정상적으로 작음 (다른 페이지 작업 중 깨짐)
3. 페이지 목적(전문가 매칭)이 채팅 시작 전에 충분히 설명되지 않음
4. 비로그인 3턴 → 회원가입 유도 → 로그인 후 12~15턴 구조를 수용할 수 있는 풀페이지 레이아웃 필요

## 레이아웃 명세

### 전체 구조

```
┌─────────────────────────────────────────────────────┐
│  NAV (공통 nav-auth.js — 로고 크기 정상화 필수)       │
├──────────────────────┬──────────────────────────────┤
│                      │                              │
│   왼쪽 패널 (40%)     │   오른쪽 패널 (60%)           │
│   마케팅 설명          │   채팅 UI                    │
│   (스크롤 없이 고정)    │   (height: calc(100vh-nav))  │
│                      │                              │
├──────────────────────┴──────────────────────────────┤
│  푸터 없음 (또는 최소한의 한줄 푸터)                    │
└─────────────────────────────────────────────────────┘
```

### 모바일 (768px 이하)

- 왼쪽 패널: 상단에 축약 배너로 표시 (2~3줄 + 아이콘)
- 오른쪽 패널: 나머지 전체 화면 채팅 UI

## 오른쪽 패널 (채팅 UI)

### 기존 로직 100% 유지

- 기존 JS 코드 (startChat, sendMessage, showResult 등) 그대로 유지
- DOM 구조 ID 변경 없음 (chatBody, msgInput, btnSend, turnBadge, resultSection 등)
- 세션 관리, 턴 카운트, 결과 카드 로직 동일

### UI 변경 사항

1. 채팅 영역 높이: `calc(100vh - nav높이)` — 세로 풀 사용
2. 채팅 헤더: 기존 "TAI 전문가 / 산업안전 전문 업체 매칭" 유지
3. 입력 바: 하단 고정 (sticky)
4. 결과 섹션: 채팅 영역 내부에서 스크롤로 표시 (현재와 동일)

## 구현 주의사항

1. **free-diagnosis.html의 nav, footer 포함 방식을 그대로 따를 것** — nav-auth.js, 공통 CSS
2. **로고 크기 확인** — 다른 페이지에서 깨진 로고 크기 원인을 찾아 이 페이지에서는 정상 크기로 적용
3. **좌측 패널은 position: sticky 또는 fixed** — 우측 채팅이 스크롤되어도 왼쪽은 고정
4. **기존 JS 코드는 <script> 블록 그대로 유지** — CSS/HTML 구조만 변경
5. **결과 카드(resultSection)도 우측 채팅 패널 안에 위치**
6. **from 파라미터 처리 추가**: URL에 `?from=diagnosis` 등이 있으면 첫 인사 메시지를 컨텍스트에 맞게 변경

## 금지 사항

- 배경 이미지 사용 금지 (허전함은 좌측 콘텐츠로 해결)
- 카카오 API 사용 금지 (알림톡, 주소검색 등)
- 기존 채팅 JS 로직 변경 금지 (sendMessage, showResult 등 함수 시그니처 유지)
