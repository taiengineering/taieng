## 왜 규정·검증이 먼저인가 (대표 통찰)

LLM은 "읽고 이해"는 하지만, 통제 안 하면 환각·과잉해석으로 폭주한다(엔진 히스토리 1·2단계).
그래서 3층 LLM은 반드시:
1. **규정** — 무엇을, 어떤 입력으로, 어떤 출력 형식으로, 무엇을 하면 안 되는지.
2. **검증방법** — LLM이 답한 주어가 맞는지 기계적으로(LLM 아닌 것으로) 확인하는 그물.
검증 그물을 통과 못 하면 LLM 답을 버린다. = LLM을 믿는 게 아니라 LLM 답을 "검증 가능한 후보"로만 쓴다.

## ★ 파일럿(C 부사구 15건)에서 드러난 핵심 약점 (v2 보완 근거)

Claude가 LLM 역할로 15건을 직접 풀어 검증 그물을 시험한 결과:
- 채택 3(도서관장/고용노동부장관/안전검사기관) / 주어없음 7 / 의무아님 5.
- **자동 3중 그물의 약점 확정:** "위원에 대하여는 수당을 지급한다"에서 "위원"은 명사(그물1 통과)이고
  원문에 있음(그물2 통과)이며 사물 아님(그물3 통과). 그러나 위원은 **수령 대상이지 지급 주체가 아님.**
  → **자동 그물은 "원문에 있는 엉뚱한 명사를 주어로 우기는 것"을 못 막는다.**
- 이것이 갈래1 사물주어·소방관 사고와 같은 한계. 자동 그물만으론 불충분.
- **결론: 자동 3그물 + 표본 글읽기(그물4)가 한 세트.** 그리고 LLM이 "주어없음/의무아님"을
  정직하게 답하게 만드는 것(추측 금지)이 그물만큼 중요. 파일럿에선 7건이 "주어없음"으로 정직히 빠져 안전.
- 부수 발견: C 부사구 유형은 보정 대상 소수(15중 3). 대부분 주어생략 또는 의무아님(위임/준용/효력).

## LLM이 푸는 대상 (2층이 못 깎은 것)

| 유형 | 규모(추정) | 왜 규칙 안 됨 |
|---|---|---|
| 갈래1 조사없음 — 조건절/수식절 깊은 주어 | ~1,950 | 주어가 문장 깊이 묻힘 |
| 갈래2 B 금지문 "~해서는 아니 된다" | 485 | 주어가 source_part 앞 또는 생략 |
| 갈래2 C 부사구 오추출 "위해서/관하여" | 261 | executor가 주어 아님. 단 다수가 주어생략/의무아님(파일럿) |
| 갈래2 SKIP_PRIOR | 260 | 어느 게 의무주체인지 의미판단 |
| NULLEXEC | 421 | 주어 생략/상속 |
| 비주어·사물 잔여 | ~400 | content_type 재검토(1층) 또는 사물주어 |
→ 합계 ~3,700. (벌칙 411 EXCLUDE_PENALTY 제외)

## 규정 (LLM에 주는 작업 명세)

### 입력
- source_part_text (원문 전체) / source_text (의미절) / content_type / 현재 executor_text(틀림)
- 자가생산 사전 1,348 주체 목록(참고).

### 작업 (딱 하나) — "의무 주체가 원문에서 무엇인가"
- 원문에 명시된 주어를 **그대로 발췌**. 새로 만들지 말 것.
- 주어 원문에 없으면 → "주어없음". 의무 아니면(벌칙/정의/위임/준용/효력) → "의무아님".

### ★ 주체 판별 규칙 (v2 추가 — 그물의 약점을 규정으로 막음)
의무 "주체"는 **그 행위를 하는 자**다. 아래는 주체가 아니다(주어로 답하지 말 것):
- **수령/대상**: "X에 대하여는/X에게는 ~을 지급/지원/적용한다" → X는 받는 대상이지 주체 아님.
  (예: "위원에 대하여는 수당을 지급한다" → 위원 ✗, 지급 주체가 따로/생략).
- **객체**: "X를 ~한다"의 X(목적어). "X에 관하여는/대해서는"의 X(화제).
- 판별법: "그 명사가 동사(하여야 한다/지급한다)를 **실행하는 쪽**인가, **받는/대상이 되는** 쪽인가."
  실행 쪽만 주체. 받는·대상 쪽이면 → 그 문장의 실행 주체를 따로 찾고, 없으면 "주어없음".
- **불확실하면 무조건 confidence:low + "주어없음" 우선.** 우기지 말 것. (파일럿 약점 직접 차단)

### 출력 형식
```json
{"executor": "<원문 발췌 주어>" | "주어없음" | "의무아님",
 "source_span": "<주어 들어있는 원문 구절 그대로>",
 "role_check": "실행주체" | "수령대상" | "객체" | "없음",   // v2 추가: 왜 주체인지 자기검증
 "confidence": "high" | "low"}
```
- role_check가 "실행주체"가 아니면 executor를 "주어없음"으로 (수령대상/객체를 주어로 못 냄).

### 금지
- 환각(원문에 없는 단어) / 임의선택(모호시 low) / content_type 변경(1층) / 원문·source_text 수정.
- BLOCKLIST: 법령형식어(B1)·수식절주어(B2)·사물(B3).

## 검증방법 (LLM 답을 믿지 않고 기계로 거른다) ★

LLM 답 executor를 **4중 그물**(v2: 그물4 명문화)로 검증. 다 통과해야 채택.

**그물 1 — Kiwi 재검증.** executor 마지막 형태소가 명사(NN*/XSN)인가. 동사·어미면 버림.
**그물 2 — 원문 발췌 검증(환각 차단).** executor가 source_part_text에 실제 존재하는가. 없으면 버림.
**그물 3 — BLOCKLIST.** 법령형식어·사물·수식절주어면 버림.
**그물 4 — role_check + 표본 글읽기 (자동그물 못 막는 "엉뚱한 명사" 차단).**
  · 자동: LLM의 role_check가 "실행주체"가 아니면 버림(수령대상/객체 탈락).
  · 사람: 채택 후보 표본 25건을 Claude/대표가 글읽기 — "이 명사가 이 의무의 실행 주체 맞나" 원문 대조.
  → 그물1~3은 환각·비명사·사물을 막고, 그물4가 "원문에 있는 엉뚱한 명사"를 막는다. 둘 다 필수.

→ 4그물 통과 + confidence:high = 채택. low 또는 실패 = needs_review.

## 작업 안전 (불변)
- LLM은 발췌·분석에만(생성/분해 아님). 코어 아닌 별도 단계 격리.
- executor_fixed에만 채움 → 4그물 + 표본 통과분만 executor_text 반영(2층과 동일).
- 원본·운영 미변경. 분해기·Kiwi사전 무변경. 배치 작게→검증→표본→확대.
- 카운트 아닌 표본 글읽기로 의미검증(카운트 함정).

## 단계
1. 유형별 소량 파일럿 → LLM → 4그물 → 표본. (C 부사구 15건 완료: 채택3/주어없음7/의무아님5)
2. 오답패턴 → 규정 보강(이 v2가 그 결과).
3. 유형별 확대. 못 푸는 것 = needs_review 최종 잔여.
4. 보정 안정 후 → 2·3층 코드화 → 원본 복사 → D단계.
