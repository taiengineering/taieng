# 3층 LLM executor 보정 — 규정 + 검증방법 (대표 발의 2026-06-14, 설계안)

> 3층 파이프라인(2026-06-14_LEGAL_PIPELINE_3LAYER.md)의 3층.
> 1·2층(분해기·Kiwi규칙)으로 못 깎은 어려운 소수를 LLM이 보정한다.
> **LLM은 규정과 검증방법 없이 작동 금지.** 이 문서가 그 규정·검증을 정한다.
> 함께 읽기: 2026-06-14_EXECUTOR_FIX_STRATEGY.md(완벽 2조건·BLOCKLIST), _ROOTCAUSE(10장 도구원칙)

## 왜 규정·검증이 먼저인가 (대표 통찰)

LLM은 "읽고 이해"는 하지만, 통제 안 하면 환각·과잉해석으로 폭주한다(엔진 히스토리 1·2단계).
그래서 3층 LLM은 반드시:
1. **규정** — 무엇을, 어떤 입력으로, 어떤 출력 형식으로, 무엇을 하면 안 되는지.
2. **검증방법** — LLM이 답한 주어가 맞는지 기계적으로(LLM 아닌 것으로) 확인하는 그물.
검증 그물을 통과 못 하면 LLM 답을 버린다. = LLM을 믿는 게 아니라 LLM 답을 "검증 가능한 후보"로만 쓴다.

## LLM이 푸는 대상 (2층이 못 깎은 것)

| 유형 | 규모(추정) | 왜 규칙 안 됨 |
|---|---|---|
| 갈래1 조사없음 — 조건절/수식절 깊은 주어 | ~1,950 | 주어가 문장 깊이 묻힘. 표면 패턴 없음 |
| 갈래2 B 금지문 "~해서는 아니 된다" | 485 | 주어가 source_part 앞 또는 생략 |
| 갈래2 C 부사구 오추출 "위해서/관하여" | 261 | executor가 주어 아님, 진짜 주어 따로 |
| 갈래2 SKIP_PRIOR (앞에 다른 주어) | 260 | 어느 게 의무주체인지 의미판단 필요 |
| NULLEXEC (주어 없음) | 421 | 주어 생략/상속 필요 |
| 비주어·사물 잔여 | ~400 | content_type 재검토(1층) 또는 사물주어 |
→ 합계 ~3,700. (벌칙 411은 이미 EXCLUDE_PENALTY 제외)

## 규정 (LLM에 주는 작업 명세)

### 입력 (LLM에 무엇을 주나)
- source_part_text (원문 전체 — 주어가 여기 어딘가 있음)
- source_text (의미절 텍스트)
- content_type, 현재 executor_text(틀린 값)
- **자가생산 사전 1,348개 주체 목록**(참고용 — 정답이 보통 이 안 또는 원문에 있음)

### 작업 (LLM이 할 일 — 딱 하나)
"이 의무(source_text)의 **의무 주체(주어)가 원문에서 무엇인가**"만 답한다.
- 원문에 명시된 주어를 **그대로 발췌**(원문 단어 그대로, 새로 만들지 말 것).
- 주어가 원문에 없으면(생략) → "주어없음" 반환. 추측해서 채우지 말 것.
- 의무 자체가 아니면(벌칙/정의/위임) → "의무아님" 반환.

### 출력 형식 (엄격)
```json
{"executor": "<원문에서 발췌한 주어 그대로>" | "주어없음" | "의무아님",
 "source_span": "<주어가 들어있는 원문 구절 그대로>",
 "confidence": "high" | "low"}
```

### 금지 (LLM이 하면 안 되는 것)
- 원문에 없는 단어로 주어를 만들지 말 것(환각 금지). 발췌만.
- 여러 주어 중 임의 선택 금지 — 모호하면 confidence:low.
- content_type 바꾸지 말 것(1층 영역). "의무아님"만 표시.
- source_text·원문 수정 절대 금지.
- BLOCKLIST 적용: 법령형식어(B1)·수식절주어(B2)·사물(B3)은 주어 아님.

## 검증방법 (LLM 답을 믿지 않고 기계로 거른다) ★핵심

LLM이 답한 executor를 **3중 그물**로 검증. 다 통과해야 채택, 하나라도 실패면 needs_review.

**그물 1 — Kiwi 재검증 (조건1, LLM 아님).**
LLM이 답한 executor를 Kiwi로 토큰화 → 마지막 형태소가 명사(NN*/XSN)인가.
동사·어미로 끝나면 = LLM이 또 동사구를 줬다 → 버림.

**그물 2 — 원문 발췌 검증 (조건2, 환각 차단).**
LLM이 답한 executor가 source_part_text에 **실제 문자열로 존재**하는가.
(공백·조사 차이 허용하되 핵심 명사가 원문에 있어야.) 없으면 = 환각 → 버림.
이것이 LLM 환각을 막는 핵심 그물: 원문에 없는 주어는 무조건 탈락.

**그물 3 — BLOCKLIST 통과.**
executor가 법령형식어(B1)·사물접미(B3)·수식절주어(B2)면 → 버림.

→ 3그물 통과 + confidence:high = 표본 글읽기 후 채택.
   confidence:low 또는 그물 실패 = needs_review(LLM도 못 푼 것, 사람 확인).

## 작업 안전 (불변)
- LLM은 **색출·분석·발췌**에만(원문서 주어 찾기). 생성/분해 아님. 코어 아닌 별도 단계 격리.
- executor_fixed에만 채움 → 3그물 + 표본 통과분만 executor_text 반영(2층과 동일 절차).
- 원본 semantic_clause·운영 미변경. 분해기·Kiwi사전 무변경.
- 배치 작게(예: 100건) → 검증 → 표본 글읽기 → 확대. 한 번에 전량 금지.
- LLM 모델·프롬프트·검증결과 로깅(어느 건을 LLM이 어떻게 답했나 추적 가능하게).

## 검증의 검증 (메타)
- LLM 보정분도 2층과 똑같이 **표본 25건 글읽기**로 Claude/대표가 최종 판정.
- LLM이 high로 답했는데 표본에서 틀린 게 나오면 → 그 패턴 규정에 반영(프롬프트 보강) 후 재실행.
- "LLM이 몇 % 맞췄나" 카운트로 판단 금지 — 표본 글읽기로 의미 검증(카운트 함정, 검증원칙).

## 단계 (제안)
1. 대상 유형별로 나눠 소량 파일럿(예: 갈래2 C 부사구 100건) → LLM → 3그물 → 표본.
2. 통과율·오답패턴 보고 → 규정·프롬프트 조정.
3. 유형별 확대. 끝까지 LLM도 못 푸는 것 = needs_review 최종 잔여(사람/대표 판단 또는 보류).
4. 전체 보정 안정 후 → 2층+3층을 코드화(파이프라인) → 원본 복사 → D단계.
