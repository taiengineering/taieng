# TAI 법령진단 오픈 검증 계획서 (V1)

## 목적

본 계획서는 법령진단 서비스의 오픈 가능 여부를 판단하기 위한 검증 계획서이다.

본 검증은

* 코드 검증
* DB 검증
* DTO 검증
* 엔진 구조 검증

이 아니다.

소비자가 입력한 정보가 실제 결과에 반영되는지 검증하는 것이 목적이다.

---

## 핵심 원칙

```text
입력이 들어갔다
(X)

입력이 결과를 바꾼다
(O)

결과 변화가 해당 입력 때문임을 증명한다
(O)
```

오픈 판단 기준은 기술적 완성도가 아니라 **입력 → 결과 변화 → 원인 설명 가능** 세 가지가 성립하느냐이다.

---

# 오픈 승인 기준

다음 조건을 만족해야 한다.

1. 주요 입력값이 결과에 영향을 준다.
2. 결과 변화가 해당 입력 때문임을 증명할 수 있다.
3. 소비자가 결과 변화 이유를 이해할 수 있다.
4. 결과가 업종·규모·위험도에 따라 상식적으로 달라진다.

---

# 검증 원칙

## 원칙 1

한 번에 하나만 변경한다.

예)

근로자 수 변경 — O

근로자 수 + 연면적 동시 변경 — X

---

## 원칙 2

기준 케이스를 유지한다.

모든 테스트는 동일한 기준 사업장을 사용한다.

---

## 원칙 3

반드시 역검증을 수행한다.

입력 변경 → 결과 변화 → 입력 원복 → 결과 원복

결과가 원복되지 않으면 FAIL

---

# 검증 단계

## STEP 1 — 정방향 검증

**목적:** 입력이 엔진까지 전달되는지 확인

**검증**

* 입력값 저장
* 엔진 전달
* 결과 생성

**합격 기준:** 전달 확인

---

## STEP 2 — 영향도 검증

**목적:** 입력이 결과를 바꾸는지 확인

**검증**

기준값 → 변경값 → 결과 비교

**합격 기준:** 결과 차이 발생

---

## STEP 3 — 역검증

**목적:** 결과 변화가 해당 입력 때문인지 확인

**검증**

기준 → 변경 → 결과 변화 → 원복 → 결과 원복

**합격 기준:** 결과가 원래 상태로 복귀

---

## STEP 4 — 소비자 검증

**목적:** 소비자가 변화 이유를 이해하는지 확인

**검증**

입력 변화 → 결과 변화 → 설명 확인

**합격 기준:** 변화 원인을 설명 가능

---

# 검증 대상

## BUILDING

| ID | 입력 |
|----|------|
| B-01 | 연면적 |
| B-02 | 층수 |
| B-03 | 승강기 |
| B-04 | 복합용도 |
| B-05 | 에너지 사용량 |

---

## INDUSTRIAL

| ID | 입력 |
|----|------|
| I-01 | 근로자 수 |
| I-02 | KSIC 업종 |
| I-03 | 위험물 |
| I-04 | 고압가스 |
| I-05 | 보일러 |
| I-06 | 수전용량 |
| I-07 | 에너지 사용량 |

---

## CONSTRUCTION

| ID | 입력 |
|----|------|
| C-01 | 공사금액 |
| C-02 | 근로자 수 |
| C-03 | 안전관리자 |
| C-04 | 고소작업 |
| C-05 | 발파작업 |
| C-06 | 잠수작업 |

---

# 결과 측정 항목

모든 테스트는 아래 항목을 기록한다.

1. 총 Rule 수
2. Applicable Rule 수
3. HIGH
4. MEDIUM
5. LOW
6. 체크항목 수
7. 정제 후 최종 결과 수

---

# FAIL 조건

다음 중 하나라도 발생하면 FAIL

1. 입력 변경 후 결과 변화 없음
2. 역검증 실패
3. 결과 변화 이유 설명 불가
4. 업종 변경에도 결과 동일
5. 규모 변경에도 결과 동일
6. 위험도 변경에도 결과 동일

---

# 오픈 승인 기준

| 섹터 | 합격 기준 |
|------|-----------|
| BUILDING | PASS 90% 이상 |
| INDUSTRIAL | PASS 90% 이상 |
| CONSTRUCTION | PASS 90% 이상 |

---

# 최종 판정

| 판정 | 의미 |
|------|------|
| **PASS** | 오픈 승인 |
| **CONDITIONAL PASS** | 경미한 버그 존재, 오픈 가능 |
| **FAIL** | 결과 신뢰성 부족, 오픈 보류 |

---

# 산출물

1. 검증 결과 보고서
2. FAIL 목록
3. 오픈 승인서

# 중요

본 검증의 목적은 **"엔진이 동작하는가"** 가 아니다.

**"소비자가 돈을 낸 만큼 결과가 달라지는가"** 를 확인하는 것이다.
