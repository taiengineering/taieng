## 2. 사용자 본질 11단계 — 작업 흐름 명문화

```
[전 단계 — 패스] 진입 필터: "필요 법령" 파악
   └ 사용자 결정 (Q1): "DB 1,322 법령 모두 검증된 필요 법령" → 패스

[1] 단일 법령 선택 (1,322 / N개씩)
   ↓
[2] Track 1부터 진행 (Track A → B → C → D → E)
   ├ Track A: validator.py 활용 (인프라)
   ├ Track B: 해당 법령의 family / citation / inheritance / delegation
   ├ Track C: 해당 법령 용어 추출 (dict 보강)
   ├ Track D: 해당 법령 별표 (Phase 1 보전)
   └ Track E: 해당 법령 Stage 1 / 2 / 3
   ↓
[3] 파싱 (extract / decompose)
   ↓
[4] 문제 발견 (검증엔진 — FP/FN 식별)
   ├ compute_stage2_sample_accuracy(law_id=N) → 정확도 측정
   ├ FP 식별 (룰별, row별)
   └ FN 식별 (UC 중 명확 패턴)
   ↓
[5] 격리 (콩과 팥 골라내기)
   ├ FP row만 is_isolated=true + isolation_reason='FP_AS_본다_보조_룰' 등
   ├ 검증된 row (TP) 그대로 보전 ★
   └ Phase 1 보전 row 변동 X
   ↓
[6] 격리 부분 분석 (1 row 단위 가능, 분석 도구 본질)
   ├ source_text 직접 분석
   ├ FP 패턴 본질 식별
   └ 룰 정정 결정 (룰 비활성 / 정정 / 신규 룰)
   ↓
[7] 파싱 개선 (룰 정정 / 신규 룰)
   ├ Phase 2.2-A 본질 (사전 단위 검증)
   ├ 룰 단위 sample 100건 ≥ 95%
   └ subtype_rule_match.py 보강 / DB UPDATE INSERT
   ↓
[8] 재파싱 (격리 row만)
   ├ is_isolated=true row만 재처리
   ├ TP 변동 X
   └ 검증된 데이터 보전
   ↓
[9] 검증엔진 PASS 도달 확인
   ├ Validator.evaluate_sample_accuracy(stage=2, ...)
   ├ ≥ 90% (마스터 §3.4)
   ├ PASS → 다음 법령
   └ FAIL/WARNING → [5]로 회귀 (격리 더 정밀)
   ↓
[10] 회귀 검증 (이전 PASS 법령 보전)
   ├ 룰 정정 후 이전 N개 법령 재검증
   ├ 회귀 X → 다음 법령
   └ 회귀 ✅ → 룰 정정 재검토
   ↓
[다음 법령] 같은 흐름 반복
   ↓
[종합] 모든 법령 PASS → 종합 sample_accuracy 자동 ≥ 90%
```
