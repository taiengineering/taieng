## 1. 핵심 전략

### 1.1 단일 메인페이지로 모든 관점 흡수
기존 문제: 방문자(안전관리자/건물주/건설사/기술자 등)마다 보고 싶은 정보가 달라 이탈률 높음  
해결책: 메인페이지에서 섹션 순서로 각 관점을 순차 노출 → 자신과 관련된 섹션에서 클릭하여 전용 랜딩 페이지로 이동

### 1.2 플랫폼 이용료 모델 (인력소개업 아님)
- 전문가·기술자와 수요자를 연결하는 것이 아니라 **플랫폼을 통한 서비스 이용 환경을 제공**
- 표현: "전문가 연결 신청" (O) / "인력 소개" (X)
- 표현: "플랫폼 이용료" (O) / "소개 수수료" (X)
- 플랫폼 내 매칭은 기업이 직접 선택, TAI는 환경 제공만

## 4. 개별 랜딩 페이지 — 스토리텔링 구조

**모든 서비스 상세 페이지 공통 구조:**

```
1. PAIN — 공감 (불편한 점으로 동질감 형성)
   "이런 상황, 겪어본 적 있으신가요?"
   → 타겟 페르소나의 고통을 구체적으로 묘사
   → 이미지/아이콘으로 시각화

2. PROBLEM — 문제 원인 진단
   "왜 이런 일이 반복되는가?"
   → 현재 방식의 구조적 문제 설명

3. SOLUTION — TAI의 해결 방식
   "TAI Safe는 이렇게 작동합니다"
   → 플로우 다이어그램 (법령진단→자동일정→작업자배정→알림→완료)
   → 스크린샷 or 목업

4. RESULT — 결과
   "이렇게 해결됩니다"
   → 수치, 케이스, 비교표

5. PRICING — 가격표
   → 해당 서비스 가격 상세

6. CTA — 전환
   → [지금 시작하기] [무료진단 먼저] [상담 신청]
```

- 결제 이력 테이블

- 상태: 접수중 / 검토중 / 매칭완료 / 완료
- 표현: "플랫폼 이용 서비스" (인력소개업 표현 금지)

### 6.5 전문가/기술자 등록 (`/mypage/register.html`)

- 설비수선 전문업체 등록

## 10. 디자인 원칙

### 10.1 기존 스킨 활용 + Vuexy 보완
- 신규 구매 스킨: 기본 레이아웃·컴포넌트 사용
- 부족한 컴포넌트: Vuexy 라이브러리에서 발췌 적용
- 색상 시스템: 스킨의 primary 색상 기준 통일

### 10.2 이미지 전략
- 텍스트 위주이지만 각 섹션에 **개념을 한눈에 설명하는 인포그래픽** 필수
- 법령진단 섹션: 체크리스트 아이콘 + 숫자 카운터 애니메이션
- SaaS 섹션: 작업 플로우 다이어그램 (법령→일정→작업자→완료)
- 전문가 연결: 수요자-플랫폼-공급자 3단계 도식
- 모든 이미지는 WebP 포맷, 최대 200KB 이하

### 10.3 반응형
- 모바일 우선 설계
- 브레이크포인트: 375 / 768 / 1280
- 메인 CTA 버튼은 모바일에서 화면 하단 고정
