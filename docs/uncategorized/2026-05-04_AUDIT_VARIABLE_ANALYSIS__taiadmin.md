## 2. V8 양방향 교차 — 진짜 그림

### 모순처럼 보였던 것

```
대표님: "4월에 100% 완료 + 검증 완료 보고를 받았던 건이다"
어제 보고: "96.9% 누락 (14,657 / 15,121)"
                  ↓
          모순 같지만 사실은 다른 단계 측정
```

### 진짜 그림

```
[4월 보고 = 1~3단계 100% 완료]
  1단계 ✅ 752 법령 선별
  2단계 ⚠️ 752 수집 (116건 본문 PDF 누락 — 5/3 발견)
  3단계 ✅ 32,808 article 파싱

[4단계 = 5/3 시점에 "미진입" 으로 본인 분류]
  - 4월에 적재된 2,583건 = 임시/탐색적 산출물
  - 본격 4단계는 5월 KEC PoC v2.10 (575건)이 첫 사례
  - 지금이 진짜 4단계 본 미션 시작점

[어제 제 보고 "96.9% 누락"]
  = 4단계가 아직 안 된 것을 "누락"이라고 잘못 표현
  = 분모도 부정확 (V1 결과 ±15% 불확실)
  = 양쪽 다 부분 진실이지만 다른 의미
```

### 결론

**4월 "100% 완료"와 지금 "미추출 14,000+"은 모순 없음**:
- 4월 = 1~3단계 100% (선별/수집/파싱)
- 지금 = 4단계가 아직 시작 안 됨

대표님이 4월에 받으신 "100% 보고" = **수집·파싱 인프라 100% 완료** (의무 추출 100%가 아님).

## 4. 본 세션 학습 (메타)

### 같은 실수 반복 패턴

```
숫자 발견 → 도메인 의미 검증 안 함 → 결론으로 가져감 → 결정 요청 → false alarm
```

### 5월 3일 정정 + 본 세션 정정

| 원칙 | 5월 3일 받은 정정 | 본 세션에서 또 위반한 사례 |
|---|---|---|
| 패턴 유사성 ≠ 결론 | "패턴 같다고 지우지 말고 본문 대조" | NFTC, 안전기준 9건, 96.9% 누락 |
| 5단계 파이프라인 명확화 | "단계마다 100% 완료 정의 다름" | 4단계 미진입을 "누락"으로 호도 |
| 변수 다 풀기 | "급하지 말고 변수 찾을 때까지" | V1만 보고 결론 시도 |

### 본 세션 적용 (앞으로)

1. **숫자 발견 즉시 결론으로 안 가져감**
2. **변수 다 풀린 뒤 종합** (V1~V8 양방향)
3. **단계별 의미 명확화** — "100% 완료"는 무슨 단계 무슨 기준인지
4. **본문 대조 우선** — 패턴/숫자보다 raw row 직접 검증
5. **모순 보이면 가설 재검토** — 두 보고가 모순이면 측정 단위가 다른 것
