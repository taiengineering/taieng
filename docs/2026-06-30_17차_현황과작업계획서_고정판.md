## 2. 돌아갈 자리 = 의무추출 고도화 (17차 본체)
정의: **Applicability → Obligation 의 법령 정확도를 높인다.** (코드 구조가 아니라 의무 데이터의 법적 정확성)

### ★ 섹터 구분 방식 (2026-06-30 정정 — 직독 확정)
이 창 초반에 Claude가 `semantic_clause`를 의무 원천으로 보고 검증하려 했으나 **한 단계 잘못 짚었음. 대표 교정 + 콘텍스트 직독으로 바로잡음:**
- **`semantic_clause.sector`(단일, COMMON 46,726…) = 예전(폐기 대상) 데이터.** `master_building_legal_rules.sector`의 COMMON/MANUFACTURING 분류는 5/9 기록상 "AI 오염, 재사용 X". COMMON 단일분류 자체가 폐기 방식.
- **`semantic_clause.sectors`(ARRAY) = 0/58,495 채움 = 의도적으로 안 채움.** 여기는 섹터의 거처가 아님.
- **대표가 만든 다중섹터(sectors) 방식의 실제 거처 = `master_rule_v2.sectors`(ARRAY).** CHECK `<@ ['BUILDING','INDUSTRIAL','CONSTRUCTION','SPECIAL_FACILITY']` 4종, NOT NULL(빈 배열 OK).
- 그 하위 객체화: **`master_rule_scope`(범위 분류: sectors/industry/building_use/facility/construction/equipment/process) + `master_rule_scope_threshold`(임계 4값) + `master_rule_scope_mapping`(M:N)**. 각각 별도 객체로 추출 → 마스터 합성(오염 격리 원칙).
- 도메인 구분: **`law_master.domain_code` 752/752 채움, 11종** (BUILDING 193 / ELECTRIC 138 / FIRE 122 / ENVIRONMENT 84 / CHEMICAL 60 / DISASTER 34 / GAS 30 / INDUSTRIAL_SAFETY 29 / ENERGY 26 / CONSTRUCTION 20 / **LABOR 16**).
- ★ 핵심 충돌(기록됨): `law_master.domain_code` 11종 ↔ `master_rule_v2.sectors` 4종. C급(노무법령 혼입)의 필터 레버는 이 domain_code(특히 LABOR)일 가능성.

→ **C급 검증의 올바른 대상 = `master_rule_v2`(+sectors, +scope) / `law_master.domain_code`. `semantic_clause` 아님.**

### 검증 기준점 (확정)
- 단일 진실 원천 = `law_article_part` (143,549행, 조문 원문).
- 의무 마스터 = `master_rule_v2` (58,495행, sectors ARRAY 보유) + `master_rule_scope`/`_threshold`/`_mapping`.
- 도메인 = `law_master.domain_code` (752행, 11종).
- 의미절(원천) = `semantic_clause` (58,495행) — 분해 산출물이며 sector/sectors는 비어있음(섹터 판정 근거 아님).
- 원칙: **건수 아닌 문장 직독**. **순환검증 금지**(파생 candidate로 검증 불가, 원문으로만). LLM은 검증 보조만, 핵심 판정 불가.

### 식별된 부정확 (VERIFY-002, factory 1427367d 기준 직독)
A(정확) 44% / B(관련) 34% / C(무관) 22% / 필수누락 8건. 원인 3종:
1. **C급 22% — BUSINESS:REGISTERED 과잉**: law_type/sector(domain_code) 필터 부재로 노무법령 혼입(장애인차별·예술인출산휴가·직기 등). → 검증 대상: master_rule_v2.sectors + law_master.domain_code(LABOR 등).
2. **키워드 의미 충돌**: 크레인→타워크레인, 고압가스→잠함 조문 오매칭.
3. **필수의무 8건 누락**: 산소농도 측정·발파 통제구역·발파 경고·발파계획·크레인 점검/자격·굴착기 작업계획서·전도방지. action_text 키워드 패턴 협소.

### applicability_conditions 직독 메모 (참고 — 별개 경로)
`applicability_conditions`는 산업안전 3법만 14건(시행령7/산안법6/기준규칙1). VERIFY-002의 C급(노무 혼입)은 이 경로가 아니라 trigger→master_rule 경로에서 발생. 인원 임계(EMPLOYEE_COUNT) 환원으로 원문의 비인원 조건(주기·직위·작업조건) 누락 경향 관찰(제129조 건강진단 주기/제16조 관리감독자 직위/제29조 교육 주기/제19조 경보설비 임계근거). 모두 **원문 대조 확정 전 후보**.

## 3. 작업 방식 (벗어나지 않기 위한 규칙)
- 한 번에 **원인 1종 × 사업장 1건**만. 의무를 조문 단위로 글로 읽어 A/B/C/누락 분류(VERIFY-002 방식).
- 코드(서비스/라우터/adapter/enum) 분석 금지. 데이터(**master_rule_v2 / master_rule_scope / law_master.domain_code / obligation**)와 조문 원문(law_article_part)만 읽는다.
- 정교화 항목만 기록, 구현·새 매핑·새 분류 제안 금지(별도 대표 승인 시에만).
- 매 STEP STOP 존중. 범위 밖으로 새면 즉시 중단.
- diagnosis_service / engine / applicability 판정계층 / master_rule 엔진 = GPT 영역. 읽기 분석만 허용, 수정 핸드오프 금지(키매칭 표면 복구 제외).
