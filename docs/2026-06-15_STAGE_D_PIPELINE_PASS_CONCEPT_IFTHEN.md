# 2026-06-15 (8부) 전체 파이프라인 그림 + "통과" 개념 + 기존 IF/THEN 겹 발견

## 한 줄 요약
대표가 전체 그림을 확정: 거름(빼기) → 섹터 → 소비자 비교 → KSIC 합집합 → 의무.
거름망을 **"남기기"가 아니라 "통과"** 개념으로 재정의. 그리고 엔진에 **이미 IF/THEN 조건
그래프(여러 겹 통과 구조)**가 있었음을 발견 — 우리 공용 거름은 그중 IF_ACTOR 한 겹.

---

## 1. ★ 대표의 전체 그림 (확정)
```
법령 전체 (비교 불가, 너무 큼)
   ↓ 공용 거름 (빼기) ─ executor가 사업장인가          ← 오늘까지 만든 것
   ↓ 섹터별 거름 (건설/건물/산업)                       ← 미설계 (통째거름 아님)
적용 가능성 남은 데이터
   ↓ 소비자 데이터와 비교 (규모·면적·공사금액)
KSIC로 뽑아온 것 ─ 소비자 데이터와 비교
   ↓ 두 개 합집합 + 중복 제거
의무조항 (소비자의 최종 의무)
```
- 대표: "이걸 해결하는 방법은 무한히 많다" → 그래서 **흔들리지 않는 원칙**으로 길을 닫아야 함.

## 2. ★ "통과(pass)" 개념 도입 (대표 통찰)
- 대표: "거름망을 거꾸로 생각하자. 추출은 타겟팅, 거름망은 범위축소. 결과적으로 둘 다 범위축소다
  (소비자 데이터와 비교해야 하니까). '남는 것'이 아니라 '통과'의 개념을 도입하면 달라진다."
- **남기기(음의 논리)**: "안 걸린 게 남음" → 왜 남았는지 약함, 보류가 모호.
- **통과(양의 논리)**: "조건을 통과함" → 통과 이유 명확(어느 관문 통과). 검증·설명 가능.
- 효과: 거름·추출·소비자비교가 **"통과하는가"라는 한 형식**으로 통일. 의무가 여러 관문 통과 = N:N.
- 위험: 통과(포함)는 "조건 없는 의무 = 탈락 = 빠짐" 위험. → **탈락 관문(명백한 비대상만 떨어뜨림)
  + 선별 관문(맞는 것 고름)**으로 분리. 현 거름망 = 탈락 관문(DROP), KEEP+보류 = 1차 통과.

## 3. ★ 발견: 엔진에 이미 "여러 겹 통과 구조"가 있었다 (대표 지적)
- 대표: "엔진에서 거름망을 여러 겹 두었었다. 마지막에 남는 것이 소비자의 의무."
- 확인: `draft_condition_graph` (10,725행) = 의무마다 **if_families → then_families** (IF/THEN 그래프).
  - if_families 예: DEADLINE_THRESHOLD / FREQUENCY_THRESHOLD / VOLTAGE_THRESHOLD / DISTANCE_THRESHOLD
    / CONCENTRATION_THRESHOLD / IF_ON_ACCIDENT / IF_OVER_THRESHOLD …
  - then_families 예: MANDATORY / REPORT / PERIODIC / INSTALL / MANAGE / PERMISSIVE …
- `draft_slot` (50,133행) = 의무를 슬롯 분해: IF_ACTOR 7,513 / THEN_ACTION 25,237 / IF_NUMERIC 2,589
  / IF_CONDITION 2,525 / IF_SCOPE 728 / EXCEPTION 535 / THEN_DEADLINE·FREQUENCY …
- **즉 각 IF_family가 한 겹의 통과 관문.** 우리 공용 거름(executor) = IF_ACTOR 한 겹에 해당.
- 결론: 공용 거름을 별도로 두지 말고 **IF_family 체계의 한 겹으로 편입**하는 게 다음 방향.

## 4. LLM 파싱 데이터로 노가다 축소 (대표 지적이 옳았음)
- 대표: "내가 LLM으로 파싱한 데이터가 있을 것. 찾으면 노가다가 준다."
- `dict_legal_terms` (14,942개) = kiwi 형태소 추출 법령 어휘. NNG 11,642 / NNP 2,832 / LAW_NAME 423
  / AGENCY_NAME 30. 단 **대표 지적**: 이건 우리 법령에서 추출한 **파생물** → 검증 기준으로 쓰면 순환.
  (원본 = law_article_part 143,549행. 검증은 원본 기준이 정본.)
- `draft_slot` IF_ACTOR를 조사 떼고 정제 → **distinct 주체 164개** (executor_text 5,197개의 1/30).
  - 이미 거름망에 있음 23 / 미분류 141. **노가다가 5,197 → 141로 축소.**
  - 단 IF_ACTOR가 "~한 자/하는 자" 행위구·깨진 조각(관한 자/대한 자) 섞임 → 추출 품질 문제(검수 필요).

## 5. 잘못 걸러낼 확률 측정 + 보정 (오늘 거름망 품질 점검)
- DROP 1,443개 글읽기 → 사업장 주체 신호("~하는 자/내는 자/받은 자")·예외("외의 자")가 든 42개 중,
  명백히 잘못 버린 11개 발견(주차장 설치자·폐기물 배출자·기간통신사업 경영자·"의료기관 외의 자" 등).
- 보정: 11개 DROP 룰 삭제 → 미매치=보류(빠짐없이). BUSINESS 안 넓힘(KEEP 아님).
- **잘못 걸러낼 확률: 약 2.6%(확실) → ~0%로 보정.** 복합 수범자("또는/및") 309개는 섹터 단계에서 재검토.
- 거름망 2,230 → **2,219개** (AUTHORITY 678 / BUSINESS 787 / FRAGMENT 566 / DELEGATED 98 / SPECIAL 90).

## 6. 다음 (이 그림으로 닫힌 길)
- **섹터 거름**을 IF_family 체계로 설계 (통째거름 아님, 한 겹). order_sensitive=true 첫 등장 예상.
- 공용 거름(IF_ACTOR)을 draft_condition_graph의 IF_family 한 겹으로 편입 검토.
- 소비자 비교 = IF_NUMERIC/IF_SCOPE 통과 판정 (수치/규모).
- KSIC 뽑기 합집합 + 중복 제거 = 최종 의무.
- 추출 품질(IF_ACTOR 깨진 조각) 검수 — 추출은 LLM/검수, 판정은 값 룰, 검증은 원본.

## ★ 흔들리지 않는 원칙 (무한한 방법을 닫는 못)
1. 거름은 순차(공용→섹터→소비자비교), 각 단계는 한 field_kind/IF_family만 본다.
2. 빼기는 명백한 것만(애매하면 보류·빠짐없이). 담기는 KSIC 공정.
3. "통과" 개념: 탈락 관문(명백한 비대상 제거) + 선별 관문(맞는 것 통과).
4. 1룰=1값(섞으면 추적 불가). 분해 후 원본 삭제.
5. 추출은 LLM+검수, 런타임 판정은 값 룰(결정적), 검증은 원본(파생물 아님).
6. 표준은 문제 생길 때마다 바꾸지 않는다.
