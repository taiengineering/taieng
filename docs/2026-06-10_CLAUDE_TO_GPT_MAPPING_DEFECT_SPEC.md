## 0. 글을 읽고 찾은 핵심 버그 (가장 중요)

분해기가 **조문 본문 속 임의의 숫자를 무조건 `employee_count`(사업장 근로자수)로
binding**하고 있다. 그 숫자의 실제 주어(subject)를 읽지 않는다.

조문 본문을 읽으면 그 숫자의 주어가 명백히 다르다:

| 조문 | 본문(글) | `>= N` 의 N의 실제 주어 | 현재 binding (오류) |
|---|---|---|---|
| 유족보상연금 대표자 선임 (산재령 §60) | "유족보상연금 **수급권자가 2명 이상** 있을 때" | 유족(수급권자) 수 | employee_count>=2 |
| 표면공급식 잠수작업 (산안기준규칙 §547) | "**잠수작업자가** 1명/2명 이상인 경우" | 잠수작업자 수 (+ 잠수작업 수행 시에만) | employee_count>=2 |
| 승강기 협회 설립인가 (§16) | "승강기사업자 **5명 이상이 발기**" | 발기인(사업자) 수 | employee_count>=5 |
| 시설물안전 협회 설립인가 (§38의3) | "안전진단전문기관 **50인 이상 발기**" | 발기인 수 | employee_count>=50 |
| 위험물 협회 설립인가 | "발기인 수" | 발기인 수 | employee_count>=10 |
| 압력용기 용접사 지정 (KEC 605.56.5) | "**용접사 1명 이상**이 작업할 때" | 용접사 수 (+ 압력용기 용접 시에만) | employee_count>=1 |
| 작업중지해제 심의위원회 (산안칙 §70) | "심의위원회는 **4명 이상으로 구성**" | 위원회 위원 수 | employee_count>=4 |

→ **요청: 조문 속 숫자의 주어(subject)를 읽어 binding_field를 결정해야 한다.
   주어가 "사업장 근로자"가 아니면 employee_count로 binding 금지.**
   (대조: "취업규칙 작성·신고 — 상시 10명 이상 근로자를 사용하는 사용자"는
    주어가 진짜 사업장 근로자라 employee_count>=10이 정상. 글로 구분 가능.)

## 1. 오매핑 조문 — 유형별 분류 (STEP2)

### CASE A. 기관/시설 지정요건 (= "지정받으려는 자"의 요건, 사업장 의무 아님)
조문 본문이 "**~로 지정받으려는 자/기관은 다음 기준을 갖추어야**" 형식.
주어가 "지정받으려는 기관"이지 진단 대상 사업장이 아니다.

- 산안법 시행령 §97 특수건강진단기관의 지정 요건 (UNRESOLVED_SCOPE+employee_count>=1)
- 산재칙 §61의3 직장복귀지원 의료기관의 지정 기준 (employee_count>=2)
- 석면피해구제법칙 §34의2 석면환경보건센터의 지정기준 (employee_count>=2)
- 전기생활용품안전법령 안전성검사기관/안전인증기관/안전확인시험기관 지정기준 (employee_count>=2)
- 화평법 시행령 §25 녹색화학센터의 지정요건 (employee_count>=8)
- 환경기술산업지원법령 §20의4 전담기관의 지정 등 (employee_count>=3)
- 재난안전산업진흥법령 §9 재난안전산업진흥시설 지정 (employee_count>=5)
- 학교복합시설 전문기관 지정 (employee_count>=3)
- 화학물질관리법칙 §35 안전교육기관 (employee_count>=3)
- 산안법칙 §193 작업환경측정기관의 지정신청 (UNRESOLVED_CONDITION)
- 작업환경측정 고시 §14 작업환경 전문연구기관 지정신청
- 조달청 안전점검 수행기관 지정
- 유해화학물질 안전교육 전문기관: 신청기관의 평가 / 평가위원회 구성

### CASE B. 위원회/협회 운영·구성 (= 행정기구 내부, 사업장 의무 아님)
- 산재칙 §9 판정위원회의 운영 ("위원장은 회의를 소집")
- 산재령 §107 재심사위원회의 운영
- 산안법칙 §70 작업중지해제 심의위원회 (4명 이상 구성 = 위원 수)
- 수도법령 §38 위탁심의위원회의 기능·운영
- 승강기/시설물/위험물 협회 설립인가

### CASE C. 제3자(유족 등) 대상
- 산재령 §60 유족보상연금 청구 대표자 선임 (수급권자=유족)
- 고용산재보험료징수법 §28의3 상속으로 인한 납부의무 승계 (상속인 대상)

### CASE D. 특정 작업 수행 시에만 적용 (해당 작업 없으면 비적용)
- 산안기준규칙 §547 표면공급식 잠수작업 시 조치 (잠수작업 시)
- KEC 605.56.5 압력용기 용접사 지정 (압력용기 용접 시)

### CASE E. 시설·설비 설치기준 (NO_CONDITION — 조건 없이 무조건 적용)
NFPC 소방 성능기준 등. 본문이 "~는 다음 기준에 적합하게 설치" 형식이고
draft_slot에 IF_SCOPE/IF_NUMERIC이 없어 무조건 통과.
- 간이스프링클러(NFPC 103A) 가압송수장치·간이헤드
- 고층건축물(NFPC 604) 피난안전구역 소방시설
- 누전경보기(NFPC 205) 설치방법
- 도로터널(NFPC 603) 자동화재탐지설비
→ 이들은 "해당 소방설비를 설치/보유한 경우"라는 scope가 있어야 하는데 없음.
  (특히 도로터널·고층건축물은 해당 시설일 때만)

## 2. 원인 유형 매핑 (STEP4)

| CASE | 원인 유형 | draft_slot 증상 |
|---|---|---|
| A 기관 지정요건 | subject 오인 + scope 미해결 | UNRESOLVED_SCOPE 또는 employee_count fallback |
| B 위원회/협회 | subject 오인 (위원/발기인 수를 근로자수로) | employee_count fallback |
| C 제3자(유족) | subject 오인 (유족 수를 근로자수로) | employee_count>=2 |
| D 특정작업 | scope 누락 (작업 수행조건 없음) | employee_count fallback, 작업조건 없음 |
| E 설치기준 | scope 누락 (시설 보유조건 없음) | NO_CONDITION |

## 3. GPT 수정 요청 사양 (조문별 예시)

```
조문: 산재령 §60 유족보상연금 청구에 관한 대표자 선임 등
본문: "유족보상연금 수급권자가 2명 이상 있을 때 1명을 대표자로 선임할 수 있다"
원래 대상(subject): 유족(수급권자)
현재 binding: employee_count >= 2  (오류: 사업장 근로자수로 오인)
오류 유형: subject 오인
수정 필요: subject=survivor (사업장 의무 아님 → 진단 대상에서 제외)
```

```
조문: 산안기준규칙 §547 표면공급식 잠수작업 시 조치
본문: "근로자가 표면공급식 잠수작업을 하는 경우 ..."
원래 대상(subject): 잠수작업을 하는 사업장
현재 binding: employee_count >= 2
오류 유형: scope 누락 (잠수작업 수행 여부 조건 없음)
수정 필요: scope = 잠수작업 수행 시. 미수행 사업장 비적용.
```

```
조문: 산안법 시행령 §97 특수건강진단기관의 지정 요건
본문: "특수건강진단기관으로 지정받을 수 있는 자는 ... 인력·시설을 갖춘 의료기관"
원래 대상(subject): 지정받으려는 의료기관
현재 binding: UNRESOLVED_SCOPE + employee_count >= 1
오류 유형: subject 오인 + scope 미해결
수정 필요: subject=기관(지정신청자). 사업장 의무 아님 → 제외.
```

## 5. 공통 권고 (분해 단계 규칙)

1. **숫자 binding 전에 주어를 읽어라**: `>= N`의 N이 "사업장 상시근로자"를
   가리킬 때만 employee_count로 binding. 위원/발기인/유족/용접사/위원회 정원 등은
   employee_count 아님.
2. **"지정받으려는 자/기관", "~위원회", "협회를 설립하려면"** 패턴은
   사업장 의무가 아님(subject=제3자/기관) → 진단 대상 제외 후보.
3. **scope 미해결(UNRESOLVED_SCOPE)이면 employee_count로 fallback 금지** —
   조건 미상으로 남겨 무조건 통과를 막아야 함.
4. **NO_CONDITION(설치기준류)**: 해당 시설/설비 보유 scope를 부여하거나,
   scope 없으면 무조건 적용을 보류.
