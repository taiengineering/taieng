**0-2. ⚠️ 법률 수치는 원문 대조 전까지 확정 아님**
조사 중 `law.go.kr` 본문 직접 조회가 반복 실패(봇 차단 추정)하여, **아래 법령 수치는 2차 출처(casenote·lbox·고용노동부 보도자료·상공회의소 자료) 기반**이다. 제품에 반영하기 전 반드시 국가법령정보센터 원문으로 대조할 것. 특히 다음은 이번 조사에서 **원문 확인 실패**:

- 중처법 시행령 제4조 **5호·7호·8호의 점검/평가 주기 문구**
- 산안법 시행규칙 별표4 **관리감독자 연간 16시간**의 2023.9.27 개정 후 유효성
- 작업환경측정 서류 **30년 연장** 규정의 정확한 조문
- 건강진단 결과 **5년/30년** 보존의 시행규칙 조번호

**0-3. EHS 전용 오픈소스는 사실상 없다**
성숙한 EHS 오픈소스 프로젝트는 존재하지 않는다(유일한 전용 프로젝트 SafetIbase는 star 17 규모). 참고 가능한 경로는 ERP(ERPNext/Odoo)의 Maintenance·Quality 모듈과 CMMS(openMAINT) 조합뿐이다. **즉 이 도메인은 "베끼면 되는 오픈소스"가 없고, 직접 설계해야 한다.**

## 2. 상세 — 규제 대응 필수 (A)

### A-1. 법정 주기 스케줄러 + 미이행 경보 ★가장 값어치 높음
**무엇** — 법이 정한 주기 업무를 캘린더로 만들고, 기한 임박·미이행을 자동 경보.
**왜** — 안전관리 SaaS가 파는 것은 결국 **"기한을 놓치지 않게 해주는 것"**이다. 아래가 전부 별개 주기다:

| 의무 | 주기 | 근거(2차 출처) |
|---|---|---|
| 유해·위험요인 확인·개선 점검 | **반기 1회 이상** | 중처법 시행령 §4 3호 |
| 안전·보건 관계법령 의무이행 점검 | **반기 1회 이상** | 중처법 시행령 §5 |
| 의무 교육 실시 여부 점검 | **반기 1회 이상** | 중처법 시행령 §5 |
| 도급·용역·위탁 기준 이행 점검 | **반기 1회 이상** | 중처법 시행령 §4 9호 |
| 산업안전보건위원회 정기회의 | **분기 1회** | 산안법 §24 |
| 안전보건교육 정기교육 | **매반기** 사무직 6h / 기타 12h | 시행규칙 별표4 |
| 도급 안전보건협의체 | **매월 1회 이상** | 시행규칙 §79 |
| 도급인 순회점검 | **2일 1회**(건설·제조 등) / **주 1회** | 시행규칙 §80 |
| 합동 안전보건점검 | **2개월 1회**(건설·조선) / **분기 1회** | 시행규칙 §82 |
| 대표이사 안전보건계획 이사회 보고 | **연 1회** (500인 이상 등) | 산안법 §14 |
| 위험성평가 정기평가 | **매년 1회** | 고시 |
| 위험성평가 최초평가 | 사업 성립일부터 **1개월 이내** | 고시 §15 |

**난이도** 중 — TAI 자동화 엔진에 시간 트리거만 추가하면 골격은 재사용 가능.
**TAI 연결** — 자동화 엔진(이벤트 규칙) + 관제홈(처리대기) + 알림. `subscription.expiring` 스캔 패턴을 그대로 확장.

### A-2. 위험성평가 모듈
**무엇** — 최초·수시·정기·상시 4가지 모드의 평가 실행, 유해위험요인 라이브러리, 빈도×강도 매트릭스, 감소대책→조치 연결, 3년 보존.
**왜** — 산안법 의무이자 **중처법 시행령 §4 3호의 반기 점검을 갈음**한다. 즉 데이터 1건이 두 법의 증적을 동시에 커버 — 이게 이 도메인 최대의 지렛대.
**난이도** 상. **TAI 연결** — 신규 도메인. 감사로그·문서 보존과 연동.
**참고** — KOSHA KRAS(무료 공공 시스템)가 경쟁자이자 레퍼런스. 업종별 템플릿·유해위험요인 표준 라이브러리 구조를 벤치마킹.

### A-3. 상시평가 간주 성립 판정기 ★차별화 포인트
**무엇** — 상시평가 3요건(**월 1회 이상** 발굴·결정·대책 / **주 1회 이상** 결과 논의·공유 / **매 작업일** TBM)의 충족 여부를 시스템이 판정해 대시보드에 표시. 예: "이번 달 발굴 0건 → 간주 불성립 경고".
**왜** — 상시평가를 채택하면 수시·정기평가를 한 것으로 간주되는데, **요건이 하나라도 깨지면 간주가 무너진다**. 이걸 사람이 추적하는 건 사실상 불가능. 경쟁 제품에서 확인되지 않은 기능.
**난이도** 중. **TAI 연결** — A-1 스케줄러 + B-14 TBM 기록.

### A-4. 법정 서류 대장 + 보존기간 자동계산
**무엇** — 서류 종류별 보존기간을 마스터로 두고, 등록 시 만료일 자동계산·알림.
**왜** — 보존기간이 **3년/2년/5년/30년으로 혼재**한다: 원칙 3년(산안법 §164), 산업안전보건위원회 회의록 2년, 위험성평가 결과 3년(시행규칙 §37), 산업재해 기록 3년, 건강진단 결과 5년, 고시물질 취급자 건강진단 30년(⚠️조번호 미확인).
**시드 데이터** — 시흥상공회의소 「안전·보건 관계서류 목록」 PDF에 서류별 법조항·근거·**과태료 금액(1/2/3차)**이 표로 정리되어 있어 마스터 테이블 초기 데이터로 바로 쓸 만하다.
**난이도** 중.

### A-5. 산재 케이스 워크플로
**무엇** — 사고 발생 → 중대재해면 **지체 없이 보고**(산안법 §54②) → **1개월 이내 산업재해조사표 제출**(시행규칙 §73, 사망 또는 3일 이상 휴업) → 원인분석 → 재발방지대책 → 3년 기록 보존.
**왜** — 미제출 과태료 1,500만원 이하(2차 출처). 기한이 촉박한데 사고 직후는 가장 정신없는 시점 — 시스템이 기한 카운트다운을 잡아주는 가치가 크다.
**난이도** 중. **TAI 연결** — B-1 사고보고 + A-1 스케줄러 + B-7 근본원인분석.

### A-6. 경영책임자 보고·서명 트레일
**무엇** — 각 점검 결과에 대해 경영책임자가 "보고받음"을 확인(전자서명/read receipt)한 타임스탬프 기록.
**왜** — 중처법 시행령 곳곳에 *"직접 점검하지 않은 경우 지체 없이 보고받을 것"* 요건이 있다. **보고받았다는 증적 자체가 별도 방어 자산**이다.
**난이도** 하 — 감사로그 인프라가 이미 있어 확장만 하면 됨. **가성비 최상위.**

### A-7. 안전보건 예산 편성·집행 트레일
**무엇** — 예산 편성안 → 집행 내역 → 용도 대비 집행률.
**왜** — 중처법 시행령 §4 4호는 *"예산 편성 및 **용도에 맞는 집행**"*을 요구. 편성 항목과 지출 전표의 매핑이 있어야 증명된다.
**난이도** 중.

### A-8. 종사자 의견청취 폐루프
**무엇** — 익명 제안·아차사고 접수함 + "청취 → 검토 → 개선 반영 여부 → **미반영 사유**" 기록.
**왜** — 중처법 시행령 §4 7호. ISO 45001 §5.4(근로자 협의·참여)와도 정확히 겹친다. 미반영 사유까지 남겨야 폐루프.
**난이도** 중. **TAI 연결** — 문의관리 구조 재사용 가능.

### A-9. 도급·수급인 평가 관리
**무엇** — 협력사 마스터 + 안전보건 조치능력 **평가기준 템플릿**·평가이력, **안전보건관리비 기준**, 건설·조선은 **공사기간/건조기간 기준** 문서고.
**왜** — 중처법 시행령 §4 9호가 이 3가지를 명시. B-12(협력업체 관리)와 같은 데이터.
**난이도** 중.

### A-10. 법령 개정 추적 ★공개 API 실재 확인
**무엇** — "우리에게 적용되는 조문"을 등록해 두고 개정을 자동 감지 → 신구법 대조표 첨부 → 영향받는 사내 규정·체크리스트·교육에 "재검토 필요" 플래그 → 담당자 태스크 자동 생성.
**왜** — 중처법 시행령 §5의 반기 법령점검 증적으로 그대로 쓰인다. 그리고 이건 **사람이 못 하는 일**이라 SaaS의 존재 이유가 된다.
**수단** — 법제처 국가법령정보 OPEN API가 실재하며 다음을 제공(직접 확인):
- 법령 **변경이력** 목록 조회 ← 핵심
- **시행일 법령** 조회 ← "곧 시행" 선제 알림
- **신구법** 목록/본문 ← 개정 전후 대조표
- **행정규칙**(고시) 조회 ← 위험성평가 지침 같은 고시 추적에 필수
- **별표·서식** 조회 ← 별표4(교육시간)·별지30호(산재조사표) 변경 감지
- 포털: https://open.law.go.kr/LSO/openApi/guideList.do
- 공공데이터포털: https://www.data.go.kr/data/15000115/openapi.do
⚠️ RSS/Webhook 푸시 제공 여부는 미확인 → **일 1회 폴링 + diff** 방식이 현실적.
**난이도** 중.

### A-11. 개인정보 파기·요청 처리
**무엇** — ① 보유기간·파기예정일 필드 + 자동 파기 배치 ② 열람·정정·삭제 요청 접수→처리→회신 트랙 ③ **수탁자(하위 처리자) 목록 공개 화면** ④ 해지 시 반출→유예→파기 3단계.
**왜** — 개인정보보호법 §21(지체 없이 파기, 복구 불가), §26(위탁계약 문서화, **수탁자 목록을 정보주체가 언제든 확인 가능하게 공개**). 안전관리 도메인은 근로자 건강진단·교육이력을 다뤄 노출도가 높다. TAI 자신이 고객사의 **수탁자**이므로 자사 하위 인프라(클라우드·SMS·메일사)를 처리방침에 공개해야 한다.
**보존 예외** — 전자상거래법상 계약·결제 기록 5년, 소비자불만·분쟁 3년, 표시·광고 6개월.
**난이도** 중(백업·로그까지 완전삭제 보증은 상).

## 3. 상세 — 제품 경쟁력 (B)

### B-2. CAPA는 모듈이 아니라 플랫폼 레이어다 ★설계 결정
VelocityEHS는 Action Management를 개별 솔루션이 아닌 **전 솔루션 공통 기능**으로 배치했다("Track and manage actions across solutions"). 사고·감사·점검·위험성평가가 **모두 같은 조치 테이블**로 흘러든다.
→ **모듈별로 조치 테이블을 따로 만들면 나중에 되돌리기 매우 비싸다.** 지금 결정해야 할 아키텍처 사항.

같은 맥락으로 VelocityEHS는 **위치(조직/사업장) 트리도 플랫폼 레이어**로 명시("Single Location Tree — 한 번 설정해 전 솔루션에 배포"). 모듈마다 사업장 마스터를 따로 두는 설계는 업계 표준과 배치된다. TAI는 이미 회사·사업장 축이 있으므로 유리한 출발점.

### B-3 / B-4. 점검과 감사는 분리한다
전 벤더가 Inspection과 Audit을 **별도 모듈**로 둔다. 주기·수행주체·법적 무게가 다르기 때문. 하나로 합치면 업계 표준과 어긋난다.

**모바일 오프라인은 선택이 아니다** — 현장(밀폐공간·지하)은 통신이 안 된다. 오프라인 미지원이면 입력률이 무너지고 **전 모듈의 데이터가 비는 구조적 실패**로 이어진다. Intelex는 오프라인+사진주석+음성메모+GPS 태깅을 명시.

### B-6. 교육과 자격은 데이터 모델이 다르다
EHS Insight는 **Training(이수 이력)과 Skills Management(보유 역량·자격)를 2개 모듈로 분리**했다. 이수 기록과 자격·면허 만료 추적은 다른 엔티티다.

### B-13. 재해통계 — ⚠️ 주의
지표 대시보드와 법정서식 생성은 전 벤더에서 확인. 다만 **TRIR/LTIFR 자동계산 필드의 제품 내장 여부는 미확인**. 공식 자체는 업계 표준: LTIFR = 휴업재해 × 1,000,000 ÷ 총근로시간, TRIR = 기록대상재해 × 200,000 ÷ 총근로시간.

### B-16 외. 벤더 카탈로그 규모의 현실
EHS Insight 36개, Intelex 37개, VelocityEHS 30여 개 모듈. 그러나 **전부 사는 고객은 없고 모듈 단위 과금**이 공통 모델. 업계 표준은 "다 만든다"가 아니라 **"핵심 축(사고-CAPA-위험성평가-점검/감사-교육-법규)을 먼저 만들고 모듈로 확장 가능한 구조"**다.

### ISO 45001 매핑 (인증 지원을 팔 수 있는 근거)
소프트웨어화 효과 순:
- **1군(즉효)**: §10.2 사고·시정조치, §6.1.2 위험성평가, §7.2 교육·역량, §9.2 내부심사, §7.5 문서관리
- **2군(데이터 연동)**: §6.1.3 법규 + §9.1.2 준수평가, §9.1.1 KPI·계측장비 교정, §8.1.4 협력사
- **3군(협업)**: §5.4 근로자 참여, §7.4 의사소통, §8.2 비상대응 훈련기록
- **4군(자동 집계)**: §6.2 목표, §9.3 경영검토, §10.3 개선 — 1~3군 데이터가 있으면 거의 자동 생성

**KOSHA-MS 관계** — KOSHA 18001 → 2019.5 KOSHA-MS로 개편. **ISO 45001 기준체계 + 산안법 요구 + ILO 권고**를 반영한 공단 독자 인증기준. 두 인증은 **상호 자동 인정이 아니다**(심사 별도). 다만 요구 프로세스가 대부분 겹치므로 **문서·기록에 ISO 45001 조항 코드 + KOSHA-MS 심사항목 코드를 이중 태깅**하는 구조가 유리. ⚠️ KOSHA-MS 47개 심사항목 세부목록과 ISO 조항 대응표는 미확인(공단 원문 확인 필요).

## 4. 상세 — 운영 어드민/CRM (C)

### C-1. 더닝(결제실패 자동 회수) ★ROI 최상위
**무엇** — 결제 실패 시 재시도 스케줄 + 유예기간 + 알림 시퀀스.
**왜** — 비자발적 이탈이 SaaS 전체 이탈의 **20~40%**. 소프트 디클라인(잔액부족)은 재시도로 **45~70% 회수**, 하드 디클라인(도난카드)은 재시도 금지. 재시도 타이밍은 고정간격이 아니라 **급여일·정산주기 기준**이 권장.
**난이도** 중. **TAI 연결** — 결제원장 + 자동화 엔진(`payment.failed` 발화 이미 결선됨) → **거의 그대로 얹으면 된다**.

### C-4. Entitlements ≠ 기능 플래그 ★혼동 주의
둘은 다른 것이고 분리해야 한다.
- **기능 플래그** = 엔지니어 소유, 임시, 배포·롤아웃 제어, 끝나면 삭제
- **Entitlement** = 상품/과금 소유, 영구, "이 계정이 이 기능을 쓸 권리가 있는가 + 한도는 얼마인가"
- 판별 질문: **"고객이 플랜을 업그레이드하면 값이 바뀌는가?" → Yes면 entitlement**
합치면 (i) 가격 변경이 개발 티켓이 되거나 (ii) 위험한 릴리스가 가격 계층 뒤에 숨는다. 코드는 `if (플래그 && entitlement)`로 합성.
**난이도** 중(entitlement) / 하(플래그 — DB 테이블+캐시면 충분).

### C-5. 임퍼서네이션 6요소
① 대리세션은 **별도 세션**(고객을 로그아웃시키지 않음) ② **시간 제한** 15~60분 ③ **해제 불가한 상시 배너** ④ **사유 입력 필수** + 시작/종료·대상·운영자 감사로그 ⑤ 쓰기 작업에 `impersonation_context` 태깅 ⑥ 계정별 **차단 플래그**.
잘못 만들면 개인정보 위반·유출 경로가 된다. 고객이 "지난 90일간 누가 우리 계정에 접근했나"에 답할 수 있어야 한다(내보내기 지원).
**권고** — 1인 운영이니 승인 게이트는 불필요하나, **읽기 전용 대리모드를 기본값**으로. 약관·처리방침에 "지원 목적 계정 접근" 명시가 전제.
**난이도** 중(최소셋) ~ 상(쓰기 전수 로깅).

### C-6. 헬스스코어 — 실무 팁 3가지
신호 4군: 제품사용(로그인+**기능 깊이**) / 지원(티켓 수·해결시간) / 관계(핵심사용자 활동) / 재무(결제실패·다운그레이드).
- **정규화** — 소형 사업장이 무조건 불건강하게 보이지 않도록
- **가치 기반 가중치** — 로그인 1~2점, 핵심 워크플로 완료 7~9점
- **드리프트 감지** — 절대 임계치 대신 "그 계정의 평소 대비 변화 속도"(정적 임계치는 명절마다 오탐 → 알림 피로)
가장 흔한 실패: "총 사용량은 정상인데 **챔피언(안전관리책임자)만 3개월째 미접속**" → 계정 단위 + 역할 단위 이중 관측 필요.
**난이도** 중. ML 불필요(데이터량 부족 시 오히려 해로움).

### C-2 / C-3 / C-7 / C-11 (난이도 하 — 빠른 성과)
- **상태페이지**: 감지 후 **10분 내 첫 공지**, 이후 **30분 간격** 업데이트, **복구(우회 포함)와 해결(항구 수정) 구분**. Instatus/BetterStack/Atlassian 등 외부 호스팅 권장 — **자사 인프라와 분리되어야 정상 동작**.
- **릴리즈 노트**: 1인 운영에서 "혼자서도 일하고 있음"을 보여주는 가장 값싼 신뢰 자산. 인앱 위젯(미읽음 카운트) + 메일 다중화.
- **셀프서비스**: 한국은 인보이스보다 **세금계산서·현금영수증 발행 상태 노출**이 실질 수요. 데이터 내보내기는 개인정보 요구사항이자 **락인 불안 해소**로 오히려 계약을 돕는다.
- **런북 최소 3개 명령**: 직전 릴리스 롤백 / DB 접속성 확인 / 정적 점검페이지 전환 — 기준은 "**새벽 3시에 생각 없이 실행 가능**".
