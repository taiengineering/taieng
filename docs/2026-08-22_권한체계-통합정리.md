## 1. 3층 가드 (`services/permission_guard.py`)

요청 처리 순서:
1. **공개(allowlist)** → 통과.
2. **인증**: 토큰 없으면 401(강제자원) / advisory 로그(비강제).
3. **Layer0 entitlement** (WRITE): 구독 없으면 403. `resource=="platform"`은 **skip**(플랫폼 운영자는 SaaS 구독자 아님).
4. **worker exempt**: 근로자 앱 route는 인증만 남기고 menu 게이트 제외.
5. **Layer1 action**:
   - 플랫폼 route(`PLATFORM_*`) → `role_permissions` 확인.
   - 테넌트 route(`menu_code` 보유) → `role_menu_permissions`의 CRUD 플래그 확인(GET=can_list·POST=can_create·PUT/PATCH=can_update·DELETE=can_delete).
   - 둘 다 아니면 게이트 없음.
6. **Layer2 scope**: 라우터 내 `company_scope`가 데이터 행을 범위로 필터(멀티테넌트 격리 + 5단).

강제 모드 env:
- `PERMISSION_GUARD_MODE` = `ENFORCE` | `ADVISORY`
- `PERMISSION_GUARD_ENFORCE` = 강제할 자원 CSV. **현재 `platform`.**
- fail-open: 가드 예외 시 통과(안전측). call_next는 try 밖 1회(이중 실행 방지).

## 5. 데이터 범위 5단 (Phase E)

- **ALL** 무필터 · **COMPANY** company_id · **FACTORY** factory_id(+company) · **TEAM** team_id · **ASSIGNED** 배정.
- 폴백: 자원에 컬럼 없으면 상위 tier로(FACTORY 컬럼 없음→COMPANY, TEAM 없음→FACTORY). fid NULL→빈결과(DENY).
- **현재**: E-1(FACTORY) `work_schedules`에 실동작(merge). 다음 자원(equipment→inspection→…) 순차 확대.

## 10. 운영 런북 (자주 쓰는 작업)

### 새 메뉴 추가 (3단계)
1. 프론트 page/route 생성(파일기반, 배포).
2. `menu_catalog` INSERT (menu_code=slug·group·sector·order).
3. `role_menu_permissions`에 대상 role×menu grant + (게이트하려면) `api_permissions.menu_code` 매핑.

### "기타" 등 메뉴 재정리 (배포 불요)
`menu_catalog`의 group_code·sort_order·is_active·sectors를 UPDATE → 새로고침 반영.

### 특정 role의 메뉴/기능 제한
manager-permission 화면에서 `role_menu_permissions`의 can_list/create/update/delete 조정. (테넌트 ENFORCE 켜져 있어야 강제됨)

### 테넌트 자원 실강제로 전환 (관측 후)
`PERMISSION_GUARD_ENFORCE`에 자원 추가(companies→factories→users…). 비-근로자 all-open이라 안전, worker route는 exempt. 각 자원 라우터의 하드코딩 게이트는 가드 커버 후 제거.

### Phase E 자원 확대
company_scope의 scoped_filter 패턴을 다음 자원 라우터에 opt-in. users.factory_id backfill 선확인.
