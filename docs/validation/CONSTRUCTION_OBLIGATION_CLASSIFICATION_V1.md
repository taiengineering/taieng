**금지 준수**: 신규 법령/의무문장 작성 0, binding 생성 0, sector filter 재작업 0. 읽기·분류만.

## 가설 교정 (Reading이 뒤집은 것)

```
종래 가설:  건설 입력 있음 → 건설 법령 있음 → 연결만 하면 됨.
Reading 결과:
  건설 법령 4,079건의 대부분은 사업장 안전 의무가 아니다.
  = 장비(건설기계) 기술기준 + 건설업 등록/면허/협회/검사대행 행정 +
    정의조항이 대다수.
  CONSTRUCTION sector = "건설 안전 의무 모음"이 아니라
    건설산업기본법·건설기계관리법 등 산업 전반 법령의 혼합.
```

## ★ A 카테고리 본문 (진짜 사업장 안전 의무 — 검증됨)

```
실제 읽은 의무 조문 (건설사업자 주체, 현장 안전 이행):

  "건설사업자와 주택건설등록업자는 안전관리계획을 수립하여
   착공 전에 발주자에게 제출하여 승인을 받아야 한다"
  "안전관리계획을 수립하는 건설사업자는 안전관리조직을 두어야 한다"
  "건설사업자와 주택건설등록업자는 공사기간 동안 매일 자체안전점검을 하고,
   정기안전점검 및 정밀안전점검 등을 해야 한다"
  "건설사업자와 주택건설등록업자는 안전교육 내용을 기록·관리해야 하며..."

= 안전관리계획 수립 / 안전관리조직 구성 / 자체·정기·정밀 안전점검 /
  안전교육 기록. 이것이 건설 사업장의 진짜 안전 의무.
```

### A 안에도 남은 미세 섞임 (GPT 선별 필요)

```
A 61건에도 주체가 다른 것이 섞임:
  "교육기관은 교육수료증을 발급해야 한다"     ← 교육기관 주체(의무 아님)
  "발주자는 ... 통보해야 한다"               ← 발주자(행정) 주체
  "발주청은 공사감독자를 선임하여야 한다"      ← 발주청 주체
→ "건설사업자/시공자가 현장에서 이행하는 의무"만 최종 선별 = GPT 법령 해석.
```

## D 카테고리 본문 (사업장 의무 아님 — binding 제외 확인)

```
"국토교통부장관은 평가위원회를 둘 수 있다"          행정청
"각 협회는 주된 사무소 소재지에서 등기..."          협회
"무한궤도식 기중기의 전도지선은..."                 장비 기술기준
"건설기계조종사 면허 정기적성검사..."               면허 보유자
"쇄석기의 표준생산능력은 ... 최대량을 말한다"        정의+장비
→ 사업장 현장 안전 의무 아님. binding 대상에서 제외.
```

## GPT 인계: binding 후보 조문 풀

```
[1순위] A_사업장 안전의무 61건
  → GPT가 본문 정독해 "건설사업자/시공자 현장 의무"만 최종 선별(주체 섞임 제거).
  → 선별된 의무에 입력조건 정의 → draft_slot/binding_field 생성.

[2순위] B_안전의무 주체불명 134건
  → 주체를 본문으로 확정 후 A로 승격할지 GPT 판단.

[제외] C 902 (비안전) + D 2,982 (장비/행정/정의)
  → 사업장 안전 의무 아님. binding 제외.

★ 입력 대응 (앞 WO 발견과 종합):
  - A의 의무는 대부분 "공통 건설 안전"(안전관리계획/점검/교육)이라
    특정 위험 입력(타워크레인/발파)보다 공사 규모/유형에 연동.
  - has_tower_crane/has_blasting/has_asbestos 같은 위험별 입력에
    직접 대응하는 "사업장 의무" 조문은 CONSTRUCTION sector에 희소.
    (위험별 조문 대부분이 장비 기술기준이었음 — 앞 HANDOFF 참조)
  → GPT 판단 필요: 위험 입력 binding을 어디에 걸 것인가
    (CONSTRUCTION 내 희소 + COMMON/INDUSTRIAL 분산분 활용 여부).
```
