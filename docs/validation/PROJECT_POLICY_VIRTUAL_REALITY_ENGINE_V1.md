# PROJECT POLICY — VIRTUAL REALITY ENGINE V1
# 운영 정책 (Operating Policy)

**작성일**: 2026-06-18
**성격**: 운영 정책. 작업지시가 아니라 의사결정 체계 규칙.
**지위**: **공식 운영 정책.** 기획서·Decision Chain과 함께 프로젝트 거버넌스의 일부.

> 목적: 가상현실 엔진(Simulation Engine) 도입 후 측정과 의사결정의 경계가
> 흐려지는 것을 방지한다. 기획서/Decision Chain/검증엔진(V4)/가상현실 엔진의
> 역할을 분리하여 프로젝트가 루프에 빠지지 않도록 한다.

---

## 1. 권한 체계 (Authority Hierarchy)

```
Level 1 — 기획서 (최상위 권한)
  권한: 프로젝트 방향 결정 / 로드맵 결정 / 완료 정의 결정
  문서: docs/2026-06-11_LEGAL_ENGINE_V4_LAYER_REDESIGN.md

Level 2 — Decision Chain (기획서 다음 우선순위)
  권한: 왜 이 결정을 했는지 기록 / 과거 판단 근거 보존
  문서: docs/validation/PROJECT_DECISION_CHAIN_V1.md

Level 3 — 검증엔진 V4 (의사결정 지원)
  권한: 정답지 기준 측정 / Coverage 측정 / FP·FN 측정
  ※ 측정만 한다. 방향을 결정하지 않는다.

Level 4 — 가상현실 엔진 (가설 검증)
  권한: 시뮬레이션 / 대량 테스트 / 우선순위 검증 / 가설 검증
  ※ 로드맵 변경 권한 없음.
```

**핵심: 권한은 위에서 아래로 흐른다. 아래가 위를 바꿀 수 없다.**

---

## 2. 금지 사항

가상현실 엔진 결과**만으로** 다음을 수행 금지:

```
새 Phase 시작        ❌
우선순위 변경        ❌
로드맵 변경          ❌
Scope 변경           ❌
구현 착수            ❌
```

금지 패턴 예시:
```
"Equipment가 중요해 보인다" (시뮬레이션 결과)
    ↓
즉시 Equipment 구현
❌ 금지

(이미 발생한 실수: SIMULATION_REPORT_V1에서 Equipment 42.4%를
 "Priority HIGH"로 판정 → 정정됨. 42.4%는 분포이지 영향도 아니었음.)
```

---

## 3. 허용 사항

기획서에서 **이미 결정된 작업**에 대해서는 가상현실 엔진 사용 가능:

```
Obligation Layer (기획서 결정 항목)
    ↓
시뮬레이션
    ↓
가치 측정
    ↓
진행 여부 판단
✅ 가능
```

즉 가상현실 엔진은 "이미 정해진 길"을 검증하는 데 쓴다.
"새 길을 내는" 데 쓰지 않는다.

---

## 4. 로드맵 변경 조건

로드맵 변경은 아래 **3개가 동시에** 충족될 때만 가능:

```
1. Golden Case 근거    (정답지가 있는가)
2. 실제 측정값          (분포 아닌 Impact가 측정됐는가)
3. 사장님 승인          (최종 승인자 동의)

→ 셋 중 하나라도 없으면 변경 금지
```

```
  Phase 1 / Phase 2 / Phase 3

⛔ Blocked:
  Phase 5 Construction (별표3 건설업란 원문 부재)

🔓 진행 가능:
  Obligation Layer (P1)
  INDUSTRIAL 확장 (P2)
```

---

## 6. Claude 행동 원칙

새로운 발견이 발생하면 **즉시 구현하지 않는다.**

```
올바른 순서:
  발견
    ↓
  측정
    ↓
  Decision Chain 기록
    ↓
  기획서와 비교
    ↓
  우선순위 재판정 요청
    ↓
  승인 후 진행

금지 패턴:
  발견 → 즉시 구현  ❌
```

---

## 7. 최종 원칙

```
기획서가 프로젝트를 이끈다.
Decision Chain이 기억을 보존한다.
검증엔진은 정확도를 측정한다.
가상현실 엔진은 가설을 검증한다.

가상현실 엔진은 프로젝트 방향을 결정하지 않는다.
```

## 부록: 이 정책이 막는 구체적 실패 패턴

```
실패 1: 분포를 영향도로 착각
  "Equipment 규칙이 42.4%니까 Equipment부터"
  → 규칙 개수(분포)와 verdict 변화율(영향도)은 다름
  → §4 로드맵 변경 조건 "2. 실제 측정값" 미충족 → 변경 불가

실패 2: 시뮬레이션 결과로 즉시 방향 전환
  "시뮬레이션 돌려보니 X가 중요해 보임 → X 구현"
  → §2 금지. 가상현실 엔진은 로드맵 변경 권한 없음

실패 3: 발견 즉시 구현 루프
  발견 → 수정 → 발견 → 수정 (15차까지 반복한 실패)
  → §6 행동 원칙으로 차단
```
