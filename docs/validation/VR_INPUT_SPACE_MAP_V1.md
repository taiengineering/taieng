# VR INPUT SPACE MAP V1
# WO-VR-INPUT-SPACE-MAP-001

**작성일**: 2026-06-20
**목적**: VR이 무엇을 흔들고 무엇을 전혀 못 흔드는지 = 입력공간 매핑.
**금지 준수**: 결론/버그판정/수정/원인분석/법령검토/개선안 없음. 매핑만.

---

## 한 줄 답: VR이 사업장의 몇 %를 흔드는가

```
현재 ACTIVE 법령엔진(applicability_conditions)의 판정 차원:
  - KSIC (업종, scope)        ← 사용
  - 근로자수 (EMPLOYEE_COUNT)  ← 사용 (유일한 수치 metric)

그 외 입력항목(설비/공정/작업/물질/건축물/에너지/저장/운반):
  - ACTIVE 조건에서 판정 차원으로 전혀 사용 안 됨.

→ VR은 "엔진이 보는 2개 차원"을 흔들고 있다.
  엔진이 안 보는 차원은 흔들 대상 자체가 없다 (흔들어도 판정 불변).
```

---

## 실측 근거

```
applicability_conditions 전체 (status·metric 분포):
  ACTIVE / METRIC:EMPLOYEE_COUNT / 14건  ← 이것이 전부

= ACTIVE 14건 전원의 수치 판정 차원이 EMPLOYEE_COUNT(근로자수) 하나.
  다른 metric(면적/물질량/용량/높이 등) 0건.
  quarantine 상태의 다른 metric도 0건.

scope 차원:
  condition_scopes = KSIC 기반 (업종 IN/NOT_IN)

→ 엔진 판정 입력 = {KSIC, 근로자수} 2개 차원뿐.
```

```

  근로자수, KSIC

NOT_COVERED (엔진 미사용):     10개
  시설/설비/공정/작업/물질/건축물/에너지/저장/운반/기타
```

## 이것이 의미하는 입력공간 크기

```
현재 VR이 흔드는 공간 = {KSIC} × {근로자수}
  = 2차원.

현실 사업장의 입력 공간 = 위 2개 + 설비/공정/작업/물질/... 다수.
  = N차원 (N > 2).

→ VR은 현재 2차원만 흔든다.
  나머지 차원은 엔진이 판정에 안 쓰므로 VR이 흔들어도
  판정이 바뀌지 않는다 = 흔들 의미가 없는 상태.

"VR이 사업장의 몇 %를 흔드는가"의 답:
  엔진이 보는 차원 기준 = 2/2 = 100% (COVERED)
  현실 사업장 차원 기준 = 2 / (2+10) = 약 17% (입력항목 수 기준)

  ※ 단 이 17%는 "입력항목 개수 비율"이지
    "사업장 위험 비중"이 아님 (그 해석은 이 WO 범위 밖).
```

---

## 관찰 (판정 아님, 매핑 사실만)

```
- 엔진은 현재 "근로자수 임계값 + 업종"으로만 의무를 판정한다.
- 그래서 VR 읽기 로그의 패턴(경계 점프/업종 편차)이 전부
  이 2차원에서만 나온 것이다 — 당연하다, 엔진이 그것만 보므로.
- 설비/물질/공정 기반 의무(예: 위험물질 보유 → 특정 의무)는
  현재 ACTIVE 조건에 metric으로 존재하지 않는다.
  → 그런 의무를 VR이 흔들려 해도 흔들 입력 자체가 엔진에 없다.

※ 왜 그런지 / 좋은지 나쁜지는 분석 안 함 (금지 준수).
  "현재 그렇다"는 사실만 기록.
```

## 결론

```
VR 입력공간 매핑 완료:

  엔진이 보는 차원 = {KSIC, 근로자수} 2개 → VR이 둘 다 흔듦 (COVERED).
  엔진이 안 보는 차원 = 설비/공정/작업/물질/건축물/에너지/저장/운반/시설/기타
    10개 → 엔진 판정 metric에 없음 (NOT_COVERED).

핵심:
  현재 VR은 "엔진이 보는 2차원"을 100% 흔들고 있다.
  그러나 그 2차원이 현실 사업장 입력의 일부일 뿐이다.
  엔진이 근로자수+업종 외 차원을 판정에 안 쓰므로,
  VR이 더 많은 차원을 흔들려 해도 흔들 입력이 엔진에 없다.

= "VR이 게으른 게 아니라, 엔진의 입력공간이 2차원이라
   VR도 2차원만 흔들 수 있다"가 현재 상태.

다음 판단(범위 밖): 입력공간을 2차원에 둘 것인가,
  설비/물질 등으로 넓힐 것인가 = 엔진 metric 설계 영역(GPT/사장님).
```
