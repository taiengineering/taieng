# VR READABLE ANOMALY CLASSIFY V1
# WO-VR-READABLE-ANOMALY-CLASSIFY-001

**작성일**: 2026-06-20
**목적**: 읽기로 발견된 이상사례를 Bug / Legal Review / Normal로 분류.
**핵심 전제**: "이상하다 ≠ 버그다." 법령 읽기 전엔 모른다.
**금지 준수**: threshold/condition/V4/Adapter 수정 0건, 법령 해석 변경 없음, 수정안 없음.

---

## 분류 원칙

```
A. Bug (명백한 엔진오류):
   법령을 읽지 않아도, 엔진 "구조/로직"만으로 모순이 드러나는 것.
   (예: 같은 사업장에 배타적이어야 할 두 구간이 동시 출력)

B. Legal Review (법령 확인 필요):
   "많아 보인다 / 적어 보인다"는 느낌이지만,
   실제 옳은지는 법령 원문을 읽어야 판정되는 것.

C. Normal (정상):
   읽어서 이상해 보였으나, 알려진 법리상 정상인 것.

※ 나는 법 1차 판독자가 아니다 (역할 분리).
  "엔진 구조상 명백한 모순"만 Bug로, 법 해석이 필요하면
  보수적으로 Legal Review로 분류한다. Normal 단정도 최소화.
```

---

## 이상사례 목록 + 분류 (AC-01, AC-02)

### 사례 1: 안전관리자 규모 구간 동시 출력 (C28, 1200명)
```
관찰:
  · "1000명 이상 안전관리자 2명"
  · "50명 이상 999명 미만 안전관리자 1명"
  → 1200명 한 사업장에 두 구간이 동시 출력.

분류: A. Bug (명백한 엔진오류) ★

근거 (법령 안 읽어도 성립):
  "50명 이상 999명 미만"과 "1000명 이상"은
  정의상 상호배타적 구간이다 (999명 ≥ 와 1000 ≤ 는 겹칠 수 없음).
  1200명은 "1000명 이상" 한 구간에만 속해야 한다.
  두 구간이 동시 출력되는 것은 수치 논리상 모순.
  = 법 해석 문제 아니라 구간 경계 로직 문제.

단, 한 가지 유보:
  만약 두 레코드가 "기본 1명 + 추가 1명 = 총 2명"을
  분해 표현한 것이라면 의도된 것일 수 있음.
  그러나 텍스트상 "1명"과 "2명"이 각각 독립 의무로 읽히므로,
  현재 출력 형태로는 사용자에게 모순으로 보임 = Bug 후보 유지.
  (최종 Bug 확정은 GPT가 엔진 구간 로직 확인 후)
```

### 사례 2: 소규모 의무 건수 (C28, 5명 → 6건)
```
관찰:
  5명 사업장에 6건 (관리감독자/위험성평가/건강진단/교육 3종).

분류: C. Normal (정상으로 추정) — 단 일부 B 혼재 가능

근거:
  산업안전보건법은 5인 사업장에도 상당수 의무가 실재한다.
  - 위험성평가, 안전보건교육, 건강진단, 관리감독자는
    규모 무관 또는 소규모도 적용되는 대표 의무.
  → "많아 보인다"는 느낌일 뿐, 6건 자체는 정상 범위로 추정.

  ※ 단 개별 의무 중 "5인 미만 적용제외" 항목이 섞여 있는지는
    법령 확인 필요 → 그 부분만 부분적으로 B(Legal Review).
  → 전체는 Normal, 개별 항목 정밀은 Legal Review.
```

### 사례 3: 50인 경계 직전 0건 (C10, 49명)
```
관찰:
  49명 → 진단서 0건 (모든 의무 미달).

분류: B. Legal Review (법령 확인 필요)

근거:
  49명에 의무가 정말 0건인지는 법령을 읽어야 안다.
  - 안전관리자 선임은 50인 기준이라 49명 미달은 맞을 수 있음.
  - 그러나 위험성평가/교육/건강진단 등 "규모 무관" 의무가
    49명에도 적용된다면, 0건은 과소(누락)일 수 있음.
  → 사례 1(C28 5명)에서는 규모무관 의무가 6건 나왔는데,
    C10 49명에서 0건이면 업종(C10 vs C28) 차이인지
    엔진 누락인지 법령으로 갈라야 함.
  = 읽기가 던진 합당한 질문. 법령 확인 전 단정 불가.

  ★ 주목: 사례 2(5명 6건)와 사례 3(49명 0건)은
    함께 보면 모순적이다 — 5명엔 6건, 49명엔 0건?
    업종 차이로 설명되면 Normal, 안 되면 엔진 누락(Bug).
    → 법령+업종 스코프 확인 필요 = Legal Review.
```

|---|---|---|---|

## 가장 중요한 성과 (사장님 지적 반영)

```
이번 단계의 성과는 "AGREE 1400"이 아니다.
"읽자마자 3개의 의심사례가 나왔다"는 사실 자체다.

= VR 검증이 살아있다는 증거.
  카운트는 다 맞다고 했지만, 읽기는 의심을 만들어냈다.
  그리고 그 의심을 바로 "버그"로 단정하지 않고
  Bug 1 / Normal 1 / Legal Review 1로 분류했다.
  → 이것이 "발견→수정" 루프에 빠지지 않는 규율.
```

## 다음 단계 (이번 WO 범위 밖, 분류만 함)


## 결론

```
읽기로 발견된 이상사례 3건 분류 완료:
  사례 1 (안전관리자 구간 동시출력) = Bug (수치논리 모순, 확정도 높음)
  사례 2 (5명 6건)                = Normal (법상 소규모도 의무 실재)
  사례 3 (49명 0건)               = Legal Review (법령+스코프 확인 필요)

"이상하다 ≠ 버그다" 원칙 준수:
  3건 중 1건만 Bug 후보, 나머지는 Normal/Legal Review.
  수정은 0건. 분류가 이번 WO의 전부.

이번 단계의 진짜 성과:
  VR이 처음으로 "사람이 읽어서 이상한 사례"를 만들어냈고,
  그것을 수정 루프 없이 분류 단계에서 멈춰 세웠다.
  = VR 검증의 목적(엔진 수정 아니라 이상사례 발견)이 작동함.
```
