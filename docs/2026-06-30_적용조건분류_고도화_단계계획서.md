## 0. 왜 이 문서를 먼저 쓰는가
17차가 순조로웠던 구간은 전부 **기획서·작업계획서로 범위를 먼저 고정**한 구간이었다. 문서 없이 작업부터 들어간 구간에서 며칠을 이탈로 낭비했다. 그래서 이 고도화도 **단계 계획을 먼저 박고**, 각 단계는 별도 WO로 끊어서 실행한다.

---

## 1. 목적 (단일)
**법령 의무가 "어떤 조건으로 발생하는가"(적용조건)를 전체 의무에 대해 정확히 분류한다.**
- 이것이 17차 본체(의무추출 고도화)의 핵심. C급(무관 의무)이 걸러지는 진짜 지점이 적용조건 분류이기 때문.
- 적용조건 유형(대표 확정, 6/23 WO-PROBLEM-001): **사업장 존재 / 업종 / 인원수 / 설비 / 공정 / 이벤트.**
- 예: 안전관리자 선임 = 업종+인원수 · 밀폐공간 교육 = 밀폐공간+작업 · 위험성평가 = 사업장 존재.

## 2. 현재 상태 (현재 DB 직독 — 표본 확인)
| 데이터 | 행수 | 의미 |
|---|---|---|
| semantic_clause(OBLIGATION) | 29,665 | **전체 의무 모집단** |
| draft_condition_graph | 10,725 | 조건 그래프 |
| obligation_quality | 1,000 | 품질평가 의무 (딱 1,000 = 표본) |
| condition_mapping_candidate | 800 | 조건매핑 후보 (딱 800 = 표본) |
| obligation_instance | 171 | 런타임 실의무 (표본 산출물) |
| law_sector_mapping | 393 | 법령↔섹터 (전체, 정상) |

→ **적용조건 분류는 전체 29,665 중 약 800~1,000(3%) 표본 위에서만 만들어졌다.** (대표 확인: "표본만으로 만든 것")
→ 섹터 매핑(393)은 정상. 고도화 대상 아님. **고도화 대상 = 적용조건 분류의 전체 확장.**

## 4. 고도화 단계 (안 — 대표 확정 전 초안)
각 단계는 **별도 WO**로 끊고, 끝나면 검증→다음 단계.

- **STEP 0 (지금)** 이 계획서 고정 + 담당경계 확정.
- **STEP 1** 표본(800~1,000)이 실제로 **어떻게** 분류됐는지 1건씩 글로 읽어 분류 스키마(컬럼·값집합) 확정. = 확장의 틀.
- **STEP 2** 표본 분류를 **조문 원문(law_article_part)과 대조**해 정확도 측정 (A/B/C). 표본 자체가 맞는지부터.
- **STEP 3** 전체 29,665로 확장하는 방식 결정 (규칙기반 우선, 경계는 GPT). 1개 의무유형(예: 선임)부터 파일럿.
- **STEP 4** 파일럿 결과 검증 → C급 감소 확인 (VERIFY-002 factory 1427367d 재측정).
- **STEP 5** 단계적 전체 확장 + 매 단계 원문 대조 검증.
※ 한 번에 1 STEP, 1 의무유형, 1 사업장. 건수 아닌 글읽기.

---

## 5. 1단계 착수점 (대기)
**STEP 1 = 표본 분류 스키마 직독.** condition_mapping_candidate(800) 또는 obligation_quality(1,000) 중 적용조건 분류를 담은 쪽을 1건씩 읽어, 어떤 컬럼에 어떤 값으로 분류됐는지 확정.
→ 대표가 STEP 1 착수 승인 시 그 테이블 구조부터 직독.
