## 0. 분석 방향 수정 (심태왕 검토 반영)

WO-ANALYSIS-001에서 SCOPE 868건 중심 분석은 **엔진이 만든 분류를 따라간 오류**였다.  
진짜 질문은: **법령 조문이 실제로 어떤 조건에 의해 발생하는가.**

SCOPE slot은 법령 적용 기준이 아니라 과거 엔진이 만든 일부 분류다.  
실제 적용 기준은 사업주 의무 조문 자체에서 읽어야 한다.

---

## 1. 분류체계 정의

| 코드 | 의미 | 발생 조건 |
|---|---|---|
| BUSINESS | 사업장 존재 | 조건 없음. 사업주 = 의무 발생 |
| INDUSTRY | 업종/사업 종류 | 특정 업종(제조업, 건설업 등) |
| EMPLOYEE_THRESHOLD | 근로자 수 임계값 | N명 이상/미만 |
| EQUIPMENT | 기계·기구·설비 보유 | 특정 기계/설비 존재 |
| EQUIPMENT_INSTALL | 설비 설치 행위 | 설치하는/조립하는 경우 |
| EQUIPMENT_USE | 설비 사용/운용 | 사용하는/운전하는/작업하는 경우 |
| WORK | 특정 위험 작업 수행 | 밀폐공간, 발파, 잠수, 석면 등 |
| MATERIAL_HAZARD | 유해물질/위험물 취급 | 관리대상, 허가물질, 소음작업 등 |
| EVENT | 특정 사건 발생 | 이상 발견, 중대재해, 점검 결과 등 |
| ROLE | 역할/인력 상태 | 보호구 지급 시, 선임한 경우 등 |
| UNRESOLVED | 참조조문 필요 | "해당하는 경우" — 조문 없으면 불판별 |

**INDUSTRY와 EMPLOYEE_THRESHOLD는 semantic_clause 단독으로 판별 불가.**  
이 조건들은 조문이 시행령 별표를 참조하며, condition_text에 수치가 직접 등장하지 않는다.  
즉 현재 1,200건 분석에서 이 두 카테고리가 2건 미만으로 나오는 것은  
파싱 오류가 아니라 **구조적 사실**: 해당 조건은 별표 데이터와 결합해야만 판별된다.

## 3. 조건 조합 패턴

분석 결과 드러난 패턴 4가지:

### 패턴 A: 단순 단일 조건 (가장 많음)
```
사업장 존재 → 의무 (491건)
특정 작업 수행 → 의무 (밀폐공간, 발파, 잠수 등)
특정 기계 사용 → 의무 (크레인, 프레스, 컨베이어 등)
```

### 패턴 B: 기계 보유 × 행위
```
[크레인 보유] × [사용하는 경우] → 의무
[화학설비 보유] × [설치한 후 처음 사용하는 경우] → 의무
[국소배기장치] × [설치 후 처음 사용하는 경우] → 의무
```
→ 이 패턴은 **equipment_assets 등록** + **상태(사용중)** 2개 입력으로 커버 가능.

### 패턴 C: 결과 × 조치 (EVENT 기반)
```
[점검 결과 이상 발견] → 즉시 보수/교체 의무
[작업환경측정 결과 초과] → 공기정화설비 설치 의무
[중대재해 발생] → 보고 의무
```
→ **실시간 이벤트 데이터 필요. 현재 입력으로 불가.**

### 패턴 D: 참조조문 기반 (UNRESOLVED)
```
"다음 각 호의 어느 하나에 해당하는 경우"
→ 조문 내 열거 항목 읽어야만 조건 판별 가능
→ semantic_clause 단독으로 판별 불가
→ 289건 (24.1%)
```


### 6-2. 핵심 발견

> **법령 적용 조건 분류체계는 이미 발견되었다.**
>
> 조건은 4개 레벨 구조다:
> 1. 사업장 존재 (무조건)
> 2. 설비/작업 보유·수행 (equipment_assets + has_* flag)
> 3. 유해인자 취급 (추가 입력 필요)
> 4. 참조조문 의존 (현재 불가)
>
> KSIC-공정-설비 3단계 triplet은 레벨 2의 **설비 추천** 역할을 한다.
> 의무 발생 조건 자체와는 별개의 계층이다.
