# 2026-06-14 D단계: 거름망 + KSIC 뽑기(C구조) 설계 검증

## 한 줄 요약
법령엔진 D단계(의미절→엔진 연결)에서, **거름망(빼기)과 KSIC 공정 뽑기(담기)를 어떻게
결합할지**를 데이터로 검증. 결론: **C구조(거름+뽑기 합집합)** 확정. 다음은 데이터 모은 뒤 결정.

---

## 1. 거름망 구조 확립 (한 망 = 한 조건)

### 원칙 (대표 확정)
1. 한 거름망 = 한 조건. (두 조건 섞으면 느리고 추적 어려움)
2. 어느 망에서 걸렸는지 trace로 추적 가능.
3. 필요한 망을 먼저 여러 개 짜둔다.
4. 하나씩 걸러보며 어느 망이 얼마나 거르는지 측정 → 순서가 데이터로 드러난다.
5. 부족하면 망을 겹으로 더 쌓는다. 한 망에 조건 추가 안 함.
6. **노가다가 효율적인 국면**: 망 규칙을 DB 테이블(`legal_sieve_rule`)에 한 줄씩.
   코드 수정 없이 행 추가로 망이 늘어남. "수백 장 돼도 빠짐없다."

### 적용대상(applicability) 망 — executor 분류
- AMBIGUOUS(보류) 글읽기로 정체 확인: 비주체명사(사항/비용/금액)와 사업주체(~하려는 자/
  건축주/시행자/신청인/제작자/수입업자)가 섞여 샘.
- 비주체명사→FRAGMENT(DROP), 신청·사업주체→BUSINESS(KEEP) 규칙 추가.
- 측정(전체 의무절 31,190 기준): AUTHORITY 12,019 / BUSINESS 6,390 / FRAGMENT 3,397 / AMBIGUOUS 9,656.
- 겹침측정: authority∩business는 대부분 "장관 또는 사업주체" 복합 수범자(사업장 포함→살림)
  → 순서 **business 먼저, authority 나중** (데이터로 발견).

### 테이블 `legal_sieve_rule`
- 컬럼: id, sieve_group, target_field, match_type(exact/regex/contains), pattern,
  verdict(KEEP/DROP), class_label, priority(작을수록 먼저), enabled, note, applies_facility_sector.
- priority 순 첫 매치 채택. 미매치 = 보류(KEEP_REVIEW, 빠짐없이).
- applicability 그룹 적재: fragment(10~20), business(30), authority(40).

## 2. sector 망 시도 → 폐기 (중요 교훈)

### 시도
- 문제: 건설 진단에 INDUSTRIAL(제조업 작업장) 의무가 섞여 KEEP됨(운반기 적재/분쇄기 덮개).
- 대표 판단: 섹터 거름을 앞단 매칭표(law_sector_mapping, 법 단위·거침)가 아니라
  **거름망(의미절 clause_sector 단위)**에서 하자. "거름이 옳다."
- sector 망 추가: 건설 사업장이면 clause_sector=INDUSTRIAL/BUILDING DROP (priority 5).
- 결과: dropped_sector_mismatch 2,293건 제거.

### 폐기 (글읽기 증거)
- 버린 INDUSTRIAL 2,293 안에 **건설현장 필수 의무**가 섞여 있었음:
  고소작업대/타워크레인/굴착/터널거푸집/강관비계/지붕작업 추락방지/안전난간/작업발판/추락방호망.
- clause_sector는 **법령 출처 분류**일 뿐 사업장 적용 여부가 아님. 산안법 기준규칙은
  산업·건설 공통이라, 섹터로 통째 거르면 양쪽 걸리는 의무가 빠짐(빠짐없이 위반).
- **sector 망 6개 전부 enabled=false (기록 보존, 삭제 아님).**

### 대표 정정 (핵심)
- "양쪽에 다 걸린다 = 같은 룰이 양쪽에 각각 있다. 그래서 걸러도 된다."
- 검증: 같은 조문은 항상 한 섹터만 가짐(sector_kinds=1, 12,971 전부). 즉 "양쪽에"는
  같은 조문 아니라 **다른 조문인데 내용 같은** 경우.
- action_text 완전일치로 교차 확인: INDUSTRIAL 고유 의무 2,141개 중 다른 섹터에 글자
  그대로 같은 것 = **34개(1.6%)뿐.** 나머지는 표현이 달라 글자로 짝 안 맞음.
- 결론: 사장님 1번(양쪽에 있으면 중복 제거)은 원리는 옳으나, 글자일치로는 실익 작고
  의미유사 판정(LLM)이 필요 → 지금은 보류, 토대로만 기록("언젠가 걸러야 한다").

## 3. KSIC 매핑 검토 (뽑아내기)

### 사실 확인
- 의미절(semantic_clause_fix)에 업종(ksic)·공정·설비 컬럼 **없음**. sector/executor/
  육하원칙만. where_text/what_text는 거의 null.
- 설비/모델/공정 테이블(equipment_*, process_equipment_map 18만행)은 **다른 사업(모델
  관찰→교체주기→수리업자 연결)의 잔재.** 지금은 안 씀.
- **지금은 국가표준 KSIC만 사용.** KSIC = 업종>공정>설비를 포함한 산업표준코드(대표 정정).
- KSIC 계층 테이블: industry_master(업종 4단계), ksic_process_map(업종→공정).

### 명사 매칭 정확도 (대표 직관 검증)
- 대표 원리: "ksic 명사 = 법령 명사." 단 단위별 정확도 다름.
- lv2 업종 정식명(긴 이름) → 법에 거의 안 나옴(0건 대부분).
- 짧은 업종 키워드(전자 1076/전기 773/가스 911) → 많이 나오나 **대부분 함정**
  ("전자문서"/"전기차단"/"유해가스" — 업종 무관). 14번 실패의 "숫자 그럴듯해도 오매핑".
- **공정명사(용접/연삭/프레스/굴착/비계/석면/해체)** → 고유해서 깨끗하게 매칭.
  글읽기 확인: "용접" 27건 대부분 진짜 용접작업 의무.
- 결론: 매칭은 **좁을수록(설비·공정) 정확, 넓을수록(업종) 함정.** 뽑기는 좁은 것부터.
  공정이 설비를 포함하는 상위라 빠짐 적음 → **공정 먼저.**

## 4. 핵심 결정: 뽑기와 거름의 순서 (C구조)

### 세 후보 (대표가 나눔)
- **A. 뽑고→거른다**: 뽑기가 관문 → 뽑기 누락 = 영구 누락. 빠짐없이 깨짐. 탈락.
- **B. 거르고→뽑기 관문**: 마지막 뽑기에서 또 누락. 탈락.
- **C. 거르고 + 뽑아서 → 합한다**: 거름망=빠짐없음 바닥, 뽑기=업종 강조(가산점). 합집합.

### 데이터 검증 (C 확정)
- 건설 사업장 의무 2,659건 중 공정명사 매칭: 걸림 1,809(68%) / **안 걸림 850(32%).**
- 안 걸린 850 글읽기: 건강진단/해고통지/출산휴가/공사대장/설계변경/사용사업관리대장 등
  **관리·노무·계약 의무.** 건설 사업장 필수인데 공정명사엔 안 걸림.
- → 뽑기를 관문(A/B)으로 쓰면 관리·노무 의무 32% 누락. **반드시 합집합(C).**

### C구조 의미 (역할 분리)
- **거름망(빼기)** = 완전성 바닥. "이 사업장이 이행할 의무인가"(executor·규모). 애매하면 남김.
  공정+관리+노무+계약 의무 전부 남김.
- **KSIC 공정 뽑기(담기)** = 업종 강조. "이 업종 공정에 특히 해당"을 위로/표시. 관문 아님.
- 두 단계 독립, 서로 관문 안 됨. 합쳐서 "빠짐없으면서 업종 맞춤."

## 5. 뽑기 토대 데이터 수집

### 테이블 `process_noun_match_stats`
- 한 행 = 공정명사 1개의 매칭 통계(noun, obligation_hits, distinct_articles, industry_count).
- 결정(쓸 명사/가중치) 전에 "표"부터 모은다.

### 수집 결과 (공정명사 768개)
- 법에 한 번도 안 나옴: **601개(78%)** (긴 정식명·물류용어)
- 쓸 만한 범위(1~200건): **143개** ← 실제 뽑기 후보
- 너무 흔함(>1000건): 8개 (검사/관리 등 일반어, 함정)
- → 쓸 수 있는 공정명사는 768개 중 약 19%(143개).
