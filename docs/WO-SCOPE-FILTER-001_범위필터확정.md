# WO-SCOPE-FILTER-001
# TAI Safe 범위 필터 확정

**작성일:** 2026-06-24 | **상태:** 완료 (범위 필터 확정 전용)
**선행:** WO-TRIGGER-EXPANSION-001
**금지:** 후보군 생성 / condition_mapping INSERT / Trigger 추가 / 입력필드 추가 / 미분류 142건 분석
**목적:** 후보군 생성 전, TAI Safe 범위 밖 조문이 후보로 들어오지 않도록 필터를 확정한다.

> 핵심 질문: 이 조문은 산업안전 진단 서비스의 대상인가?

---

## 결론 먼저

```
전체 사업주 의무 1,572건 중 191건이 범위 밖.

OUT_주택법       109
OUT_파견법        37
OUT_공동주택관리   24
OUT_보험료징수     19  ← 신규 발견
OUT_근로기준        2
─────────────────
범위 밖 합계      191건 (12.2%)

→ NO_TRIGGER 76건은 일부였다.
→ CONNECTED에도 범위 밖이 섞여 있었다 (191 - 76 = 115건).
→ 범위 필터를 Trigger 매핑보다 먼저 적용하면 191건 제거.
→ 실제 TAI Safe 대상 = 1,381건.
```

## 산출물 A: IN_SCOPE 정의

```
IN_SCOPE = 산업안전보건법 + 중대재해처벌법 + 시설안전 직접 의무

판정 기준:
  ① executor가 산업안전보건법상 사업주/도급인/관계수급인/건설공사도급인
  ② 의무 내용이 근로자 안전·보건·작업환경
  ③ 시설·설비·작업·물질의 안전관리

포함 법령:
  산업안전보건법 (본법·시행령·시행규칙)
  산업안전보건기준에 관한 규칙
  중대재해처벌법
  건설기술진흥법(안전관리계획)
  시설물안전법(건물 진단 범위)
```

## 산출물 B: OUT_OF_SCOPE 법령군

| law_name | exclude_reason | executor_text | why_out_of_scope |
|---|---|---|---|
| 주택법 | 분양·공급 시행사 의무 | 사업주체 | 주택 공급/분양/사용검사는 산업안전 아님 |
| 파견근로자보호법 | 인력파견 계약 의무 | 파견사업주/사용사업주 | 파견계약·고용 의무, 작업안전 아님 |
| 공동주택관리법 | 아파트 관리 의무 | 관리주체 | 관리비·장기수선·입주자 의무 |
| 고용보험·산재보험료징수법 | 보험료 납부 | 사업주 | 월별보험료 납부, 안전관리 아님 |
| 근로기준법(일부) | 휴가·모성보호 | 사업주 | 출산·육아휴직, 작업안전 아님 |

```

              분양, 사용검사, 간선시설

보험료징수:   보험료, 월별보험료, 보험가입, 징수
```

## 산출물 C: executor 혼동 규칙

**같은 단어라도 법이 다르면 대상이 다르다.**

| executor | 소속 법령 | 판정 | 근거 |
|---|---|---|---|
| 사업주 (산안법) | 산업안전보건법 | **IN_SCOPE** | 근로자 안전보건 의무 주체 |
| 도급인 | 산업안전보건법 | **IN_SCOPE** | 도급 시 안전조치 |
| 관계수급인 | 산업안전보건법 | **IN_SCOPE** | 수급인 안전조치 |
| 건설공사도급인 | 산업안전보건법 | **IN_SCOPE** | 건설 안전관리 |
| **사업주체** | 주택법 | **OUT_OF_SCOPE** | 분양 시행사 |
| **파견사업주** | 파견법 | **OUT_OF_SCOPE** | 인력파견업체 |
| **사용사업주** | 파견법 | **OUT_OF_SCOPE** | 파견 사용업체 |
| **관리주체** | 공동주택관리법 | **OUT_OF_SCOPE** | 아파트 관리소 (HOLD) |

### 판정 원칙

```
"사업주"만으로는 판정 불가.
반드시 본문 키워드로 소속 법령을 확인한다.

산안법 사업주:    "근로자가 ...작업/취급/사용하는 경우" + 안전조치
주택법 사업주체:  "주택의 공급/분양/입주자/사용검사"
파견법 파견사업주: "근로자파견/파견근로"
보험료 사업주:    "보험료/징수/납부"

→ executor_text + (source_text || action_text) 동시 검사.
```

## 산출물 E: 후보군 생성 적용 순서

**범위 필터는 Trigger 매핑보다 먼저 적용한다.**

```
후보군 생성 파이프라인:

1. law_name / 본문 SCOPE FILTER     ← OUT_OF_SCOPE 191건 제거
       ↓
2. executor SCOPE FILTER            ← 산안법 사업주/도급인만
       ↓
3. semantic_clause ROLE FILTER      ← OBLIGATION/PROHIBITION만
       ↓
4. FRAGMENT EXCLUSION               ← "이 경우" 등 격리
       ↓
5. TRIGGER MAPPING                  ← 입력→Trigger→법령
       ↓
6. 후보군 생성

→ 1~2단계(범위 필터)를 통과하지 못하면 Trigger 매핑 자체를 안 함.
→ 분양·파견·관리비 의무가 공장에 매핑되는 오류 원천 차단.
```

## 산출물 F: 76건 재현 검증

```
WO-TRIGGER-EXPANSION-001의 NO_TRIGGER 76건 재현:

전체 사업주 의무 1,572건에 필터 적용 시:
  OUT_주택법       109 (76건 중 52 포함 + CONNECTED에 섞인 57)
  OUT_파견법        37 (76건 중 13 포함 + 24)
  OUT_공동주택관리   24 (76건 중 8 포함 + 16)
  OUT_보험료징수     19 (신규 — NO_TRIGGER 미분류에 있던 것)
  OUT_근로기준        2 (76건 중 2 포함)

✅ 재현 성공.
→ NO_TRIGGER에서 발견한 76건은 빙산의 일각이었음.
→ 실제 범위 밖은 191건 (76 + CONNECTED 혼입 115).
→ CONNECTED에도 범위 밖이 섞여 있었다는 게 핵심.
   (예: 보험료 납부가 "UNIVERSAL"로 잘못 분류됐을 가능성)
```

### 검증의 의미

```
만약 범위 필터 없이 후보군을 생성했다면:
  CONNECTED 1,025건 중 약 115건이 범위 밖 조문.
  → 공장 진단 결과에 "주택 분양 의무", "보험료 납부",
    "파견근로 계약" 이 섞여 나왔을 것.
  → 명백한 오탐. 신뢰도 붕괴.

→ 범위 필터를 Trigger 매핑 앞에 두는 것이 필수.
```

## 산출물 G: HOLD 정책

이번 후보군 생성 1차에서는 제외하되, 향후 활성화 가능:

| 영역 | 현재 | 향후 |
|---|---|---|
| 공동주택관리법 일부 | 제외 | 건물관리 서비스 확장 시 활성화 |
| 시설관리 관련 법령 | 제외 | 시설관리 서비스 추가 시 |
| 에너지 관련 (에너지이용합리화법) | HOLD | 건물 에너지 진단 확장 시 |
| 소방 관련 (소방시설법) | HOLD | 소방 점검 연계 시 |
| 승강기 관련 (승강기안전관리법) | HOLD | 승강기 점검 연계 시 |

```
주의: 소방·승강기·에너지는 BUILDING 진단에 부분 관련.
  has_sprinkler, has_elevator, is_energy_intensive 입력이 이미 존재.
  → 완전 제외가 아니라 HOLD.
  → 1차 후보군에서는 산업안전보건법 핵심만.
  → 2차에서 소방·승강기·에너지 활성화 검토.
```

## 성공 기준 답변

```
Q: 어떤 법령은 후보군 생성 전에 제외되는가?
A: 주택법·파견법·공동주택관리법·보험료징수법·근로기준법(휴가).
   총 191건.

Q: 사업주와 사업주체를 어떻게 구분하는가?
A: executor 단어만으로 불가. 본문 키워드로 소속 법령 확인.
   "사업주체+분양/입주자" = 주택법 = OUT.
   "사업주+근로자 안전조치" = 산안법 = IN.

Q: 범위 필터가 Trigger 매핑보다 먼저 적용되는가?
A: 그렇다. 1.범위필터 → 2.executor → 3.role → 4.fragment → 5.trigger.

Q: 76건 OUT_OF_SCOPE가 재현되는가?
A: 재현됨. 오히려 191건으로 확대 (CONNECTED 혼입 포함).
```

## 핵심 발견

### 발견 1: 범위 밖이 NO_TRIGGER보다 컸다

```
NO_TRIGGER에서 본 76건 → 실제 191건.
CONNECTED에도 115건의 범위 밖이 섞여 있었음.
→ 보험료 납부가 UNIVERSAL로 분류됐을 가능성.
→ 범위 필터 없이는 89% CONNECTED 중 일부가 오탐.
```

### 발견 2: 보험료징수법 신규 발견 (19건)

```
"월별보험료를 다음 달 10일까지 납부"
→ 산재보험료징수법. 안전관리 아님.
→ executor가 "사업주"라 산안법으로 오인되기 쉬움.
→ 본문 "보험료/징수" 키워드로만 식별 가능.
```

### 발견 3: 필터 순서가 정확도의 핵심

```
범위 필터를 Trigger 매핑 뒤에 두면:
  범위 밖 조문도 Trigger가 붙어 후보가 됨 → 오탐.

범위 필터를 앞에 두면:
  애초에 Trigger 매핑 대상에서 제외 → 오탐 원천 차단.

→ 17회차 오탐의 구조적 해결책.
```
