## 0. 한 줄 요약

고객이 마이페이지에서 **자동견적을 미리보고 스스로 발행**하거나 **개별견적을 요청**하고, 운영자는 어드민 **매출·결제 > 견적서**에서 개별요청을 **작성·발행**하거나 **직접 견적을 작성·발행**한다. 발행된 견적은 **TAI 브랜드 견적서 PDF**로 다운로드된다. 견적은 계약·결제·세금계산서와 연결되지 않는 **내부결재/구매검토용 편의 문서**다.

## 1. 기획 배경 & 제품 계약

### 1.1 목적
- 기존 마이페이지 "계약 관리"는 스텁 상태였다. 이를 **"견적서 발급"** 기능으로 신규 구축(D급 재설계).
- 견적서 = **고객사 내부 구매/결재 자료용 편의 문서**. TAI가 고객사의 내부 결재를 대행/관리하지 않는다.

### 1.2 절대 금지 개념 (전 구간 공통)
견적 도메인에서 아래 상태·개념·연결을 만들지 않는다:
- 상태: `CONFIRMED` / `APPROVED` / `PENDING_PAYMENT` / `PAID` / `CONVERTED` / `CONTRACT_CREATED` / `CUSTOMER_APPROVAL` / `INTERNAL_APPROVAL`
- 연결: 계약 생성 / 결제 요청 / 세금계산서 발행 / 전자결재 / 고객 승인
- 관리자 행위는 "승인"이 아니라 **"견적 작성 → 견적서 발행"**이다.

### 1.3 중복 SoT 금지 원칙
- 가격 SoT = `price_master` 테이블 (프론트 하드코딩 금지)
- 저장 = 기존 `quotes` 테이블
- 소유권 = 기존 `company_scope` (`/me/*` 자사 강제, `_require_admin`)
- PDF 저장 = 기존 `document_svc`
- 신규 테이블/컬럼은 필요성이 증명될 때만 (원칙적으로 migration 0)

## 2. 데이터 모델 (`public.quotes`)

발행/요청 견적은 모두 단일 `quotes` 테이블에 저장한다. 핵심 컬럼:

| 컬럼 | 타입 | 비고 |
|---|---|---|
| `id` | uuid | PK |
| `quote_no` | text | `QT-YYYYMMDD-XXXXXXXX` (원자 재시도로 유일성 보장) |
| `company_id` | uuid | 고객사 |
| `company_name` | varchar | **발행 시점 snapshot** (이후 회사명 변경 무영향) |
| `created_by` | uuid | 생성자(고객 또는 관리자) |
| `source` | varchar | `member_auto` / `member_custom` / `admin_manual` / (legacy) `survey_web` … **enum/CHECK 없음** |
| `status_code` | varchar | `ISSUED` / `REQUESTED` … **enum/CHECK 없음** |
| `contact_name` | text (nullable) | 담당자명 snapshot (기존 컬럼 재사용) |
| `contact_phone`, `contact_email` | text | 존재하나 이번 기능 미사용 |
| `items` | jsonb | 품목 snapshot 배열 (현 버전 단일 품목) |
| `survey_data` | jsonb | 개별요청 원문(`member_custom` 네임스페이스) |
| `supply_amount`, `vat_amount`, `total_amount` | numeric | 상위 금액 = items[0] 금액과 일치 |
| `created_at`, `updated_at` | timestamptz | 발행일 파생에 사용 (별도 `issued_at` 컬럼 없음) |

> **핵심**: `source`/`status_code`가 varchar이고 CHECK 제약이 없어 `admin_manual`/`ISSUED` 등을 **migration 없이** 저장 가능 (GATE-0 = PASS-A 근거).

### 2.1 `items[0]` snapshot 형태 (PDF consumer 정본)
```
price_id, service_type, sector, tier_code, display_name,
billing_unit, unit_amount, term_months, quantity,
supply_amount, vat_rate, vat_amount, total_amount
```

## 3. 백엔드 API 계약

### 3.1 회원(고객) — `/me/quotes/*` (자사 소유권 강제)
| Endpoint | 용도 | 핵심 규칙 |
|---|---|---|
| `POST /me/quotes/auto/preview` | 자동견적 미리보기 | **DB write 0, PDF 0**. contact_name 정규화 echo. 가격은 `price_master` 서버 계산 |
| `POST /me/quotes/auto` | 자동견적 발행 | `source=member_auto`, `status=ISSUED`. items snapshot, quote_no 부여 |
| `POST /me/quotes/custom` | 개별견적 요청 | `source=member_custom`, `status=REQUESTED`, 금액 0, 요청내용 `survey_data`에 저장 |
| `GET /me/quotes` | 내 견적 목록 | `member_auto`/`member_custom`만 |
| `GET /me/quotes/{id}` | 상세 | 자사 아닌 건 404 (존재 은닉) |
| `POST /me/quotes/{id}/pdf` | PDF 발급 | 발행(ISSUED) 건만. 멱등 재사용 |

**가격 계약**
- SAAS: `billing_unit=MONTHLY`, `supply = unit_amount × term_months`, 할인 없음
- DIAGNOSIS: `billing_unit=ONCE`, `quantity=1`, 기간배수 금지
- CUSTOM 티어: `amount ≤ 0` → 409 `CUSTOM_QUOTE_REQUIRED` (+`route_to_custom=true`)
- VAT: `row.vat_rate` 사용(하드코딩 금지), `vat = round(supply × vat_rate)`, `total = supply + vat`

### 3.2 운영자(관리자) — `/admin/quotes/*` (`_require_admin`: role scope=ALL만)
| Endpoint | 용도 | 핵심 규칙 |
|---|---|---|
| `GET /admin/quotes` | 목록 | `ADMIN_SOURCES`(member_auto/member_custom/admin_manual)만, survey_web 제외. source/status/search 필터 |
| `GET /admin/quotes/{id}` | 상세 | 그 외 source는 404 |
| `POST /admin/quotes/manual/preview` | 관리자 직접견적 미리보기 | write 0. 회사 strict 조회(미존재 404). 서버 금액 계산 |
| `POST /admin/quotes/manual` | 관리자 직접견적 발행 | `source=admin_manual`, `status=ISSUED`, 신규 row |
| `POST /admin/quotes/{id}/custom/preview` | 개별요청 발행 미리보기 | `member_custom/REQUESTED`만. row immutable, write 0 |
| `POST /admin/quotes/{id}/custom/issue` | 개별요청 발행 확정 | **same-row conditional UPDATE** REQUESTED→ISSUED |
| `POST /admin/quotes/{id}/pdf` | 관리자 PDF | `_require_admin` 후 발급. 고객 `/me` 가드 우회 아님 |

**관리자 견적 가격(협의/비정형)**
- `member_auto`는 `price_master` 정본 유지.
- `member_custom`/`admin_manual`은 **관리자 입력값(unit_amount·billing·기간/수량·vat_rate)을 서버가 재계산**. 브라우저 계산값 미신뢰(요청 body에서 금액 필드 제외).
- 서버 계산: MONTHLY `supply=unit×term`, ONCE `supply=unit×qty`, `vat=round(supply×vat_rate)`, `total=supply+vat`.

**발행 무결성 (핵심 계약)**
- **"발행 성공 = 즉시 PDF 완결 가능"**: 발행 전에 PDF validator 상위 필수 5필드(`id/company_id/quote_no/company_name/created_at`) + `display_name`(품목명) + 회사 존재를 검증. 누락 시 409/404로 발행 자체 차단(master 재조회 보충 금지).
- **관리자 override 금지**: 개별요청 발행 시 `service_type`은 기존 row, `sector`는 `survey_data.member_custom.sector`에서만. 관리자는 상품/티어/과금/기간·수량/단가/vat/메모만 입력.
- **불변 보존**: custom 발행(REQUESTED→ISSUED) 시 `quote_no·company·contact_name·survey_data·created_at·created_by·source` 미변경. 변경분은 `items·금액·status·updated_at·memo`.
- **중복 발행 방어**: conditional UPDATE(`source=member_custom AND status=REQUESTED`) 0행이면 409 `QUOTE_ALREADY_ISSUED`.

### 3.3 공개 카탈로그 (가격판정 SoT 아님, UI 렌더용)
- `GET /public/pricing/saas-plans?sector=` / `GET /public/pricing/diagnosis-reports?sector=`
- `price_master` 활성행 반환(tier_code·display_name·sub_label·features·amount·vat_rate·billing_unit·is_recommended…).
- **역할 분리**: 카탈로그 API = 선택 가능한 상품 목록 SoT / preview API = 실제 견적 금액 SoT. 카탈로그 `amount`로 최종 금액 재계산 금지.

## 4. PDF 엔진 & 견적서 양식

### 4.1 렌더 파이프라인
- 템플릿: `templates/quotes/member_quote_v1.html` (Jinja2, autoescape) — **파일명 고정(드롭인), TEMPLATE_VERSION만 v2**
- 렌더러: **Gotenberg**(Chromium) — `POST {GOTENBERG_URL}/forms/chromium/convert/html`
  - `GOTENBERG_URL`은 env-only, 하드코딩 금지. 운영값 `http://gotenberg.railway.internal:3000` (내부 DNS, 포트 3000)
  - 미설정 시 503 `PDF_RENDER_CONFIG_MISSING` (localhost/public fallback 금지)
- 저장: `document_svc.register_generated` (bucket=`company-docs`, category=`general`, source=`AUTO_GENERATED`, linked_table=`quotes`)
- 멱등키: `GENERATED_BY="member_quote_pdf_v1"` (불변). 재요청 시 기존 문서 재사용
- 서명 URL 실패 시 503 `PDF_DOWNLOAD_UNAVAILABLE` (false-success 방지)

### 4.2 TAI 전용 견적서 양식(v2)
한국 표준 견적서 관례 + TAI 브랜딩:
- 네이비(#0d2b4e) 브랜드 헤더 바 "TAI 엔지니어링 / TAI SAFE"
- "견 적 서" 대제목, 견적번호·견적일자
- 수신 블록: **담당자 없으면 `{회사명} 귀중`, 있으면 `{회사명}` + `담당: {담당자} 귀하`**
- 공급자란(세금계산서 공급자 박스 스타일): 등록번호/상호/성명+**직인(㊞)**/주소/업태·종목/전화·이메일/FAX
- 품목표(서비스/상품·티어/기간/수량/단가/공급가액), 합계(공급가액·부가세·합계금액), 한글금액(金 …원정)
- footer 면책: "계약서·결제확정서·세금계산서가 아닙니다"
- 외부 asset 0(폰트/로고/CDN 금지, self-contained), A4 1page

### 4.3 발행일자 계약
- `member_auto` / `admin_manual` (ISSUED): `created_at`
- `member_custom` (ISSUED): `updated_at` (= 관리자 발행 시점 = 실 발행일). 누락 시 created_at fallback

### 4.4 공급자 정보 (env)
`TAI_CORP_NAME`, `TAI_CEO_NAME`(대표자 — `TAI_CORP_CEO` 아님), `TAI_CORP_NUM`, `TAI_CORP_ADDR`, `QUOTE_SUPPLIER_TEL`, `QUOTE_SUPPLIER_EMAIL` (필수), `QUOTE_SUPPLIER_FAX`, `TAI_BIZ_TYPE`, `TAI_BIZ_CLASS` (선택).

## 6. 고객 마이페이지 UI (tai-www)

- 위치: `src/pages/mypage/contracts/` + 메뉴 라벨 "계약 관리" → **"견적서 발급"**
- 로직: `public/assets/js/tai-quote-issue.js` (분리)
- **3경계 분리**: PREVIEW(계산결과, quote/PDF write 0) / ISSUE(quote row + frozen snapshot + quote_no) / PDF(저장 snapshot 출력)
- 자동견적 흐름: **서비스 → 섹터 → (동적 카탈로그) 티어 → (SaaS만) 기간 → 미리보기 → 발행 → 발행본 웹뷰 → PDF 다운로드**
  - 티어는 `/public/pricing/*` 동적 로드(프론트 하드코딩 제거). 서비스/섹터 **라벨 매핑만** 하드코딩 허용.
  - 미리보기 화면 = 승인 PDF v2의 웹 축약판. 견적번호/발행일/PDF 버튼 없음.
- 개별요청 탭: 서비스·섹터(**자유 텍스트 입력**)·제목·내용·담당자 → `POST /me/quotes/custom`. 접수 후 "견적 작성 중", PDF 버튼 없음.
- 목록: `canPdf = status_code === 'ISSUED'` (source 고정 아님 → 관리자 발행된 custom도 PDF 노출)
- **프론트 가격계산 금지**: annualDiscount/×기간/VAT/합계 계산 금지, backend 응답 표시(콤마 포맷)만. `company_id` 등 식별자 전송 금지.

## 8. 고객 ↔ 관리자 핸드오프 (개별요청 전 흐름)

```
[고객] 마이페이지 개별요청 제출  → member_custom / REQUESTED (survey_data에 요청원문)
      ↓
[관리자] 매출·결제 > 견적서 목록 "견적 작성 중"
      → [견적 작성] : 요청 컨텍스트 readonly + 상품/기간/단가 입력
      → 미리보기(견적서 폼) → 견적서 발행
      ↓  same-row conditional UPDATE (quote_no·회사·담당자·요청원문·created_at 보존)
      member_custom / ISSUED
      ↓
[고객] 마이페이지 그 견적 "발행 완료" → PDF 다운로드 (담당자 표시 포함)
```

관리자 직접견적(admin_manual)은 회사 검색·선택 후 작성→미리보기→발행→상세/PDF.

## 10. 거버넌스 (작업 방식)

- 역할 분리: **Claude**(기획·read-only 검증·PR 생성/merge 실행) / **GPT**(독립 게이트, PASS/FAIL 판정) / **Cursor·Claude Code**(구현). Claude는 자가 PASS 선언 금지.
- 매 단계: 구현 → PR([DO NOT MERGE]) → Claude 실 diff 소스검증 → GPT 게이트 → (PASS 시) squash merge → 배포 → smoke/E2E.
- PRE-MERGE GUARD: state=open/merged=false, EXPECTED HEAD·BASE 일치, mergeable, CI SUCCESS 전부 확인 후에만 merge.
- 검증 원칙: 보고문 신뢰하지 않고 실 소스/diff 직접 조회. "발행=PDF완결"은 실 발행 결과를 PDF validator에 투입해 실증.
